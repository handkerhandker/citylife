# 语言指纹真模型验证工具（voice-check）

## 这是什么，为什么需要它
第 13 单的教训：**桩测试只验条款是否写清，不验真模型是否遵守**。桩全绿而线上仍连招，已实证这个缺口。
本工具用**真模型**跑生产提示词，量化统计开场类型分布、招牌起手式次数、明喻次数——每次改动 `AI_VOICE`
或 `styleAssign` 都应复测，不得只凭桩绿交付。

## 关键性质：提示词与生产逐字节相同
脚本不重写任何提示词。它直接从 `city-life-framework.html` 抽取 DOM 层的
`AI_VOICE` / `hungerWord` / `styleAssign` / `agentCard` 源码求值，并复用 `runReflection`、
`enhanceMessage` 里提示词表达式的原文，配合真实 `Sim` 世界状态生成。`lastUtterance` 的写入也逐字
复刻 `noteUtter`（压空白、截 80 字）。因此代码一改，提示词自动跟着变，无需同步维护第二份副本。

## 用法

工作目录默认 `tools/voice-check/.work/`（可用环境变量 `VC_OUT` 改）。该目录是临时产物，勿提交。

### 日记通道（一轮覆盖四人，推荐）
```
node tools/voice-check/collect_diary.cjs init          # 生成第 1 轮提示词 → .work/round_prompt.txt
# 把 round_prompt.txt 原样发给真模型（线上通道即 /relay，背后 DeepSeek），拿到 JSON 回包后：
node tools/voice-check/collect_diary.cjs next '<回包JSON>'   # 记账并生成下一轮
# 重复至第 6 轮，自动写出 .work/real_gens.json（四人各 6 条）
node tools/voice-check/measure.cjs                     # 规则侧统计
```

### 单人通道（短信，用于排除"批量调用摊薄注意力"这一混淆项）
```
node tools/voice-check/collect_sms.cjs init
node tools/voice-check/collect_sms.cjs next '<回包JSON>'
```

### 接线上中转站
在能连通部署站的环境里，把 `round_prompt.txt` 的内容作为 `prompt` POST 给 `/relay` 即可：
```
curl -s -X POST https://<你的站点域名>/relay \
  -H 'Content-Type: application/json' \
  --data-binary @<(python3 -c "import json,io;print(json.dumps({'prompt':io.open('tools/voice-check/.work/round_prompt.txt',encoding='utf-8').read()}))")
```
回包形如 `{"text":"..."}`，把其中 `text` 的 JSON 交给 `next` 即可。
（**注意**：站点域名与密钥都不写进仓库——域名见 EdgeOne 项目配置，密钥只在其环境变量里。）

## 开场类型分布怎么统计
`measure.cjs` 只做规则侧能可靠判定的两项：**招牌起手式**（按句型正则，逐人不同）与**明喻**
（`像…`／`跟…似的`／`如同`／`仿佛…`；裸「一样」多为「也一样＝同样」故不计，「像样」是固定词也不计）。

**开场四类**（说事／吐槽／问话／接话）无法用正则可靠判定，须人工或另找一个模型盲标。盲标口径：
只看开头第一小句，给出四类＋「招牌」共五选一；**不要把配额指标告诉标注者**，避免自证。
判定标准：连续 6 次中四类覆盖 ≥3、无相邻同类、招牌 ≤1、明喻 ≤2。
