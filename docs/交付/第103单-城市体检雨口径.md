## 一 · 缘由

第 23 单换尺时的原话（`sim30.js` 注释）：

> 「门禁要量的东西若不在 `w.stats` 里，就在门禁侧逐拍观测，**不给世界加字段**。」

那条规矩是给**门禁**立的（门禁自己观测、不动世界）。可**面板**是产品的一部分——它要把"现在的雨况"说给玩家听，
而它一直只报场次；`待办.md` 里这条挂了很久（第 23 单已知接受项 ①）。
本单按产品口径补上这笔账：**面板与门禁从此说同一句话**。

## 二 · 设计

```js
// advance10 末尾（**起雨／停雨两段之后**）：
if(!isFinite(w.stats.rainMin)) w.stats.rainMin=0;   // 旧档／坏值就地重建
if(w.weather.rain) w.stats.rainMin+=10;             // 本拍结束时在下雨 ⇒ 记 10 分钟
// 面板：
$('#mt-rain').textContent=S.rain+' 场 · '+(雨分/全长*100).toFixed(1)+'%（'+Math.round(雨分)+' 分钟）';
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| **口径与门禁同尺** | `sim30` 的 `rainTicks+=w.weather.rain?1:0` ×10 | 同一拍、同一个字段、同一时刻读（**这条闸自己就守着顺序**） |
| **必须排在起雨／停雨之后** | 放在 `advance10` 末尾、`clipTick` 之前 | ★本单第一版放在"停雨之后、起雨之前"，于是**每一场雨都少记第一拍**：30 天实测 5560 vs 6080，正好差 52 场×10 分钟 |
| **旧档／坏值就地重建** | `isFinite` 判一下再从 0 起算 | 照 `goalOf`／`rhyRest` 那一套；绝不在字符串上做加法 |
| **面板拆行** | 雨单独一行，发薪／交租／街市另起一行 | 一行只讲一件事，读数才读得清 |
