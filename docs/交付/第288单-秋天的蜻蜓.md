## 三 · 选址与工具的三处坑（都是本单自己撞的，照实登记）

1. **江面不能放**：铺满模式下江面（第 24–27 行）正是屏幕最下沿——横屏几乎出画、竖屏压在底栏后面。
   第一版把 5 只锚在江面上，目验时从裁切图里**一只都看不见** ⇒ 改锚到**岸线步道（第 23 行）**，
   仍是"水边"（紧贴江面）。
2. **西段岸线不能放**：实测 UI 木盒——日志浮层在竖屏盖住**列 8.4–17.5**、横屏盖住**列 0.6–20.1**
   （`F:\临时\2026-10-08\dragonfly288\measure-ui.mjs`）⇒ 5 只锚全部挪到**列 21.5 往东**，
   两种朝向都干净（这也是 harness 闸一那条"列 ≥21.5"判据的来历：**"看得见"也是判据的一部分**）。
3. ★**探针脚本自己的坑**（三个，都会把结论带偏）：
   ① `page.evaluate('() => {...}')` 这种**字符串表达式在本机没被执行** ⇒ 六张"场景图"其实全是默认态；
   ② 仓库路径写成正斜杠字面量 ⇒ `path.join` 规范化成反斜杠后 `startsWith` 判假 ⇒ 素材 404、
      量到的是"色块兜底路"（A/B 三态实测：正斜杠＝`ready:false`、`path.resolve` 带不带 MIME 都 `ready:true`）；
   ③ 想用"关掉蜻蜓前后各数一次"的 A/B 时，用**嵌套 rAF** 等下一帧——多 context 下页面会被判后台、
      rAF 停摆 ⇒ 脚本挂死（已按 PID 精确收掉），改成 `waitForTimeout` 即好。
   这三条与第 287 单登记的两条同类：**临时脚本的坑会伪装成产品结论**。
