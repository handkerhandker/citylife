# 第 93 单 · 欠人情排队（收了人家几份，就还几份）

> 一句话：第 87 单的回礼只记**最后一份**——生日那天被三个人各送一份，他回头只欠最后那位一份（另两份白收）。
> 本单把 `ag.giftRecv` 从**单个对象**改成**一队**：先收的先还、**一天最多还一份**、**过期的逐条作废**；
> 旧档（第 87 单那种单对象写法）一律当"只有一条的队"，照常还得出去。
> 版本：v85 → **v86**。指纹：世界 `b5935386…` 与门禁 `d759a1f6…` **原样**，SIM 块 md5 `c583763e…` → **`2813ccb0…`**。

## 一 · 缘由

第 87 单交付时登记的第一条接受项：

> **一天里收到多份，只记最后一份**（`giftRecv` 是个单值，不是队列）——生日那天被三位邻居各送一份，
> 他只欠最后那位一份。要改就得把 `giftRecv` 变成数组，属另一单。

本单就是那一单。**构造实测**（与上一版并排跑，见 3.2）：三人各送一份时，旧版一共回 **1** 笔，新版回 **3** 笔。

## 二 · 设计

```js
function 欠账队(ag){                       // 旧档兼容：单个对象 ⇒ 当"只有一条的队"
  const q=ag&&ag.giftRecv;
  if(!q) return [];
  if(Array.isArray(q)) return q.filter(x=>x&&typeof x==='object'&&isFinite(x.t));
  if(typeof q==='object'&&isFinite(q.t)) return [q];
  return [];
}
function 记欠账(寿星, 送礼人, w){          // 收一份记一条（原来只记最后一份）
  const q=欠账队(寿星); q.push({ t:w.t, from:送礼人.id, fromName:送礼人.name }); 寿星.giftRecv=q;
}
// decide() 回礼那一支：
const 队=欠账队(ag);
const 留=队.filter(x=>w.t-x.t<GIFT.backMax);          // 过期的**逐条**作废（不连累别人那份）
const 头=留.find(x=>w.t-x.t>=GIFT.backMin);           // 先收的先还
if(头 && 同屋 && 对方空闲){ 还掉这一条; return; }        // 一天最多还一份（这一支 return 掉了）
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| **先收的先还** | 按入队顺序取第一条到点的 | 礼数讲"先来后到" |
| **一天最多一份** | 那一支 `return` 掉 | 一天还三份太急，也不像过日子 |
| **过期逐条作废** | `留=队.filter(...)` 后写回 | 第 87 单那条"过了 13 天就不惦记"照旧，只是不再牵连别人 |
| **旧档兼容** | `欠账队` 认单个对象 | 老存档不该因为改了形状就废掉（照 `goalOf`／`rhyRest` 那套"宁可缺省也不判坏档"） |
| **落点不变** | 仍然记在**收礼人**身上 | 欠人情的是收的人（第 87 单那条口径没动） |

## 七 · 已知接受项与顺带发现

1. **一天最多还一份**：三笔欠账要三天还清——这是刻意的（一天还三份不像过日子）。
2. **顺序是"先收先还"**：不按关系深浅挑（那是 B 档的事）。
3. **★顺带发现（只登记，不改）**：**生日礼物在自然跑里很罕见**——把"同屋 ＋ 寿星在窗内空闲"这两条摆在一起，
   自然跑 30 天只有 **0–1 份**（三颗种子实测；本单那支探针要**摁住四人**才拿到 3 份）。
   第 81 单那节门禁同样是构造出来的。要不要让礼物更容易发生（例如放宽到"留在家门口"）属另一单。
4. **旧档不会追溯**：老存档里那份"只剩最后一位"的欠账，就按一条算——这是照实办事，不假装知道他欠过谁。
