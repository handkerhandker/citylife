# 第 71 单 · 夜谈话题（坐着到底在聊什么）

> 一句话：上一单把「夜谈角」变成真有人去的地方，但坐下那条日志只写"听人说话"——
> **坐着聊什么，没人知道**。本单给每一场夜谈定一个**话题**：写进坐下那条日志，也写进散场播报。
> 指纹：**只有 SIM 块 md5 变**（`7ea77b99…` → **`e6ddaa57…`**），世界与门禁指纹**逐字节原样**——
> 这是一次**纯文案**改动（话题不改任何行为与状态），正是宪法第 26 条那类"世界指纹覆盖不到"的单。
> 版本：v68 → **v69**。

## 一 · 缘由

第 70 单交付时我自己登记了第一条"已知接受项"：夜谈**只是坐着，没有专属话题**。
它当晚就显出别扭来——玩家看到四个人坐在夜里，头上的牌子写着「夜谈」，日志却只写"听人说话"。
一场夜谈该有它今晚在聊的那件事。

## 二 · 设计（零素材、零 AI、零新状态）

```js
const TALK_TOPICS=['这周的雨','楼下那家便利店','阳台上晾的东西','月底那笔房租',
                   '江边的灯','广场的夜市','最近的觉够不够睡','手里的活和欠的稿'];
function talkTopicOf(w){ const d=Math.max(0,PURE.dayOf(w.t)-1);
  return TALK_TOPICS[((d*2654435761)>>>0)%TALK_TOPICS.length]; }
```

| 要件 | 落成 | 为什么这么做 |
|---|---|---|
| 今晚聊什么 | 按**日号**哈希取一条（**不摇 rng**） | 照第 52 单派活那条先例：确定性、可复现，且不位移事件流的抽签 |
| 粒度 | 写到「地点／事由」即止（"这周的雨""楼下那家便利店"） | 照第 18 单 `TOPIC_POOL` 的口径：不写到具体物件，留口吻的余地 |
| 落点一 | 坐下那条日志：`在夜谈角坐下，听人说话（今晚聊：X）` | 在场每个人看到的都是同一个 X |
| 落点二 | 散场播报：`夜谈散了，今晚聊的是「X」，坐了 N 个人。` | 播报从"报人数"升级成"报这一场聊了什么" |
| 同一晚一致性 | 两处**调同一个函数**（日号相同 ⇒ 结果相同） | 20:00 与 22:00 读到的必然是同一句 |

## 七 · 已知接受项与盲区（照实登记，不粉饰）

1. **话题只是"题面"，不影响说什么**：四人坐在一起仍走既有闲聊那套（随机开口／接话），
   并不会真的围着这个话题说。要"话题带着台词走"得动闲聊池（第 48 单那套分组），属另一单。
2. **话题按日号哈希，一周一条**：夜谈只在周日发生，所以实际是"每周换一条"；池子 8 条 ⇒ 八周一轮。
   要更多就加池子（`TALK_TOPICS` 一处）。
3. **没做"雨天话题"**：本来想让下雨天聊"这场雨什么时候停"，但那要读 `w.weather`——
   而 20:00 与 22:00 两处的天气**可能不一样**，为保"同一晚两处一致"这条判据，本单**先不做**（照实登记）。
4. **话题不进剪辑层**：夜谈仍靠既有的社交判据上卡，没有为它单开一项。
