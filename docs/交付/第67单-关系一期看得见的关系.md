# 第 67 单 · 关系一期：把"谁跟谁熟"摆到台面上（零新增世界状态）

> 一句话：本作从第 48 单起就在记"谁跟谁说过话"（每场闲聊往 `w.stats.pair` 记一笔），
> 但**玩家一处都看不到**——想知道谁跟谁熟，只能去日志页一行行翻。
> 本单把它摆出来：**角色卡**与**角色详情**各一行「常聊」，形如「和 陆知秋 聊过 42 次」。
> **只动呈现层**：不新增世界状态、不动 SIM 块、不掷骰子 ⇒ 世界指纹与 SIM 块 md5 **逐字节原样**，
> 只有界面版本涨号 v66 → **v67**。

## 一 · 缘由（已经有了数据，却没有出口）

待办里"关系状态机"挂着很久，而第 64（生日）、第 65（生日问候）、第 53（周记忆）、第 54（目标进剪辑）
四个单都在等它——它们都只能把"心意"落在文案上，因为没有可读的关系数值。

真正的状态机要**改结构**（新增随事涨落的关系值、进目标谓词、进剪辑判据），照母法改动分级得先出方案、
等决策者点头。所以本单**只做一期**：先把**已经存在**的那份账（`w.stats.pair`）变成看得见的东西——
零风险、可验证，而且它本身就是状态机的天然底座（将来有了数值，这一行的取词口不用改）。

## 二 · 设计

```js
function relText(w, ag){          // 一处取词：与他有关的那几对里，取次数最多的一个
  ... 遍历 w.stats.pair，只认 "自己id+对方id" 的两人键 ...
  return n>0 && mate ? ('和 '+mate.name+' 聊过 '+n+' 次') : '还没跟谁聊过';
}
```

| 落点 | 变化 |
|---|---|
| 角色卡（角色页四张卡） | 新增一行 `kv`「常聊」＋ 每帧用 `relText` 刷新（与"目标／上周"同一处刷新块） |
| 角色详情对话框 | 原来那行只有总数（"累计 N 次来往记在心里"，看不出**跟谁**）——现在写「和 X 聊过 N 次（累计 N 次来往）」 |

**口径写在词里**：报的是"**聊过 N 次**"（累计自开局），不是"最近"——不拿旧账冒充新账。

## 七 · 已知接受项与盲区（照实登记，不粉饰）

1. **是累计账，不是"最近"**：报的是自开局以来的次数。想要"最近和谁聊得多"得有一扇滚动窗——
   那需要新状态（正是二期状态机那件事），不在本单。
2. **只显示"聊得最多的那一个"**：第二名、第三名不显示；同数时按对象键的遍历顺序取先见到的那个（确定性，但语义上是"并列随便取一个"）。
3. **没有"关系好／坏"的判断**：本作只记"聊过几次"，没有亲疏、没有正负。一期**不发明**数值——
   那正是要决策者点头的那一步。
4. **关系状态机（二期）仍未开工**：本单只是把它的底座摆到台面上。方案要点（新增 `ag.rel[对方id]`、
   随闲聊／生日问候／玩家短信涨落、进目标谓词与剪辑判据）建议单独立单、先出方案。
