# 第 84 单 · 名牌字号随缩放（治第 32 单登记的第一条遗留）

> 一句话：名牌字号从第 32 单起就**写死 10px**，而房间名走的是 `clamp(9,12,s*0.7)`——
> 镜头缩得越小、名牌相对越宽（手机上四个名字能糊成一条黑杠）。本单把两者并到**同一把尺**：
> 字号＝`clamp(9,12,s*0.7)`，盒高与道距都**从字号推**（盒高＝1.5×字号），分道逻辑一字未改。
> 指纹：**三个数全部原样**（纯渲染层），只有界面涨号 v79 → **v80**。

## 一 · 缘由

第 32 单（名牌分道）交付时照实登记了两条遗留，第一条就是它：
> ① 名牌字号仍写死 10px（只治"叠"，不治"不随缩"）

第 42 单的取证工具也把这条量成了数（"字号占精灵高度的比例"随缩放漂）。

## 二 · 设计（一处定义、只动名牌那一块）

```js
const 名号  = () => Math.max(9, Math.min(12, state.view.s*0.7));   // 与房间名同一把尺
const 名盒高 = () => Math.round(名号()*1.5);                        // 盒高从字号推
// nameChip：盒顶 = y − 盒高 + 1 − 道×盒高；底仍是 y+1（与第 32 单同构，只是高度不再写死）
```

**为什么名牌不借 `chip()` 画底**：`chip()` 的盒高写死 15、字号一变就露馅，而它还被房间名／地标名／
活动指示器共用——动它等于动全站。名牌这块于是**自己画底**，只改自己（第 31 单"另起一行画"那条口径的延续）。

## 七 · 已知接受项与盲区（照实登记，不粉饰）

1. **名牌与房间名"压不压"仍靠让位表**：重叠计数在放大档会变多（名牌更大），但房间名会被让掉不画——
   这是第 42 单定的口径，本单没动。
2. **字号上限仍是 12**（与房间名同上限）：要再大就得同时抬房间名，否则名牌会压过房间名一整档。
3. **没调道距系数（1.5×字号）**：它保证盒与盒之间不贴脸；要让牌子更松就改这一个数（`名盒高`）。
4. **没有"按人名长度分档"**：三个字与两个字的名字用同一字号（只按缩放），没做自适应。
