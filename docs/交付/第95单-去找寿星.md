# 第 95 单 · 生日礼物（二）：找不到人就走过去 ＋ 一对人一年一次

> 一句话：第 94 单把"机会来了能兑现"修好了，可自然跑 400 天仍只有 3–4 份礼——两个原因：
> **机会全靠巧合**（要有人恰好空闲着、又恰好在寿星那间屋），以及 `ag.giftYear` 是**一个人一年一个数**
> （当年第一个过生日的人把三个人的礼都用掉了，后面三个生日一份也没有）。
> 本单两处：**还没送过的人会主动走到寿星那间屋**（到了下一拍礼物自然递出去；**一步 rng 都不摇**），
> "一年一次"改成**一对人一年一次**。结果：自然跑 400 天 **3–4 份 → 11–12 份**。版本：v87 → **v88**。
> 指纹：世界 `b5935386…` 与门禁 `d759a1f6…` **原样**，SIM 块 md5 `959a4011…` → **`9d6b7ab3…`**。

## 一 · 缘由：把上一单剩下的两个瓶颈接着修

第 94 单交付时登记的两条"仍挂着的"正好就是这一单要做的：

> ① **真实机会本来就少**（3–4 拍／400 天）——要让礼物更常发生，得让**邻居主动去找寿星**（新行为，另立单）；

另外实测还查到第二条：**礼物全落在当年第一个生日那天**（D72 沈小满），后面 D158／D262／D330 三个生日
**一份礼都没有**——因为 `giftYear` 是"一个人一年一个数"，三个邻居在 D72 就把这一年的礼都用掉了。

## 二 · 设计

```js
/* ① 找不到人就走过去（不摇 rng：死分钟数、null 独白、不走 pickV/tempoDur） */
if(ag.giftYear!==年){ … }                       // 老写法是"一个人一年一个数"
const 寿=w.agents.find(o=>o!==ag && inBirthday(w,o) && 醒着(o) && !给过(ag,o.id,年));
if(寿 && roomOf(寿.anchor)!==roomOf(ag.anchor)){
  setActivity(w,ag,寿.anchor,'stroll','去找'+寿.name,20,null,'去找'+寿.name);
  return;                                        // 走到下一拍，礼物那一支自然把东西递出去
}
/* ② 一年一次 → 一对人一年一次 */
function 给过(ag,id,年){ …ag.giftYears[id]===年… || ag.giftYear===年（旧档） }
function 记给过(ag,id,年){ ag.giftYears[id]=年 }
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| **走过去** | `setActivity(…寿.anchor…,20,null,'去找‹寿星›')` | 礼物要"当面"——那就别等巧合；路程由 `setActivity` 那 +10 分钟一并算上 |
| **不摇 rng** | 死分钟数 ＋ `null` 独白（不调 `pickV`／`tempoDur`） | 这一支只改"走不走"，不改"摇不摇"；门禁里有 `rngState` 逐字节比对 |
| **睡着不打扰** | `醒着(o)`（第 94 单那条口径） | 不追着睡觉的人跑 |
| **一对人一年一次** | `ag.giftYears={对方id:年}` | "不刷礼"那条本意一字没改，只是把账记在**对人**上 |
| **旧档兼容** | 老的 `giftYear`（数字）仍认 | 那年给过谁已不可考 ⇒ 当年一律不再给；下一年自动走新账 |

## 七 · 已知接受项

1. **他会"找一趟"**：如果到了发现寿星又走了，下一拍他会再找一遍（窗口 15:00–22:00 内，一趟 30 分钟）——
   这是刻意的"把心意送到"，不是路径规划 bug。
2. **睡着的人不打扰**：22:00 前就寝的人收不到礼（与第 94 单同一条）。
