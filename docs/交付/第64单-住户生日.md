# 第 64 单 · 住户生日（把"年"这把尺从城市推到人）

> 一句话：第 62／63 单把日历尺推到"年"，但那是**城市**的节日（全城同一晚去江边）。
> 本单补上**个人**那把：四个住户各有一个生日，一年一次——**晨报提前 3 天提一句＋当天提一句**，
> 生日当天**他本人**给自己买块蛋糕（−¥12），**玩家短信「生日快乐」在当天发会得到不一样的回应**。
> 指纹：**世界与门禁原样、只有 SIM 块 md5 变**（`c0cc198d…` → **`fcd47cbf…`**）——
> 四人的生日里最早的是 **D72**，而那两个指纹只看**头 30 天**，窗口走不到；**靠构造证**（第四节）。
> 版本：v64 → **v65**。

## 一 · 缘由（城市有节日了，人还没有生日）

第 62 单给了城市一个"年"，第 63 单把它撑成三天并接进目标系统。但那一整套都是**全城同一件事**：
四个人在同一天晚上做同一件事。真正让"人"立起来的，是**只属于他自己**的日子——
同类作品里最普遍、最便宜、也最动人的一条就是生日。本单做它。

## 三 · 设计（零素材、零 AI、零新锚点）

```js
const BIRTHDAYS={ a1:{month:6,dayOfMonth:8}, a2:{month:3,dayOfMonth:12},
                  a3:{month:11,dayOfMonth:30}, a4:{month:9,dayOfMonth:22} };
const BDAY={ cost:12, noticeDays:3, cake:'小块奶油蛋糕', open:15*60, close:22*60 };
```

| 要件（照调研） | 落成 | 判据 |
|---|---|---|
| 提前预告 | 晨报在**生日前 3 天**加一句「再过 3 天是顾云帆的生日。」 | 构造：恰一句 |
| 当天再提 | 当天晨报加一句「今天是顾云帆的生日。」 | 构造：恰一句 |
| 生日那天有件属于他的事 | 当天 **15:00–22:00** 空闲时，他去买块蛋糕 **−¥12**（一年一次，`ag.bdayYear` 去重） | 构造：恰一次、¥12、次日不再 |
| 上卡 | 那一刻把日志原文抄进 `ag.lastBday`（第 59 单"落笔抄录"口径），剪辑层出 **甲级 2.6** 一项 | 结构 ＋ 构造（当天卡里带它） |
| 同一份心意，当天分量更大 | 短信表加「生日快乐」；**当天发**走 `REACT.birthdayToday`，平时发走 `REACT.birthday` | 构造：两条反应文案不同 |

**口径**：只占**空闲时间**那一档（上班／吃饭／睡觉一概不碰）；生日撞上周五夜市时**生日优先**
——与第 62／63 单同一条取舍（一年一次 > 每周一次）。**买蛋糕那一步不掷骰子**：他的日子，必买
（可计数、可复现）。

## 八 · 已知接受项与盲区（照实登记，不粉饰）

1. **生日项不是每次都上卡**（24 次里 17 次）。缘由是剪辑层的既有规则：**一天一张卡、只挑一个人**
   （"谁今天最不像平常的自己"）。生日那天若另一个人有更大的落差（例如"处境·逆"3.0 ＋ 晚睡 2.0），
   卡就归那个人。**不为此加特例**——生日当天的可见性由晨报那句与他自己那条日志保证（两处都必现）。
2. **祝福只有两个落点**：反应文案 ＋ 周记忆（`ag.week.信`）。本作**还没有关系状态机**，
   没有"好感度"这类数值可加——那条挂在 `待办.md` 的"关系状态机"里，等它立起来再回头接。
3. **日历仍是自造的**：12 个月 × 30 天 ＝ 360 天（第 62 单定义）。生日挂在它上面；
   将来若要真日历，这套要一起改。
4. **住户之间不会互相祝贺**。动森那条是"村民张罗"——本作要动闲聊池（第 48 单那套分组与熵闸），
   属另一单；本单只做"他自己 + 玩家"这两方。
5. **日期是我挑的**（散在一年、避开江灯节 D45、避开每月 2 号的交租日），不是从人物设定推出来的；
   要改就是改 `BIRTHDAYS` 一处。
