## 一、机理报告（先取证，再下刀）

交接说明第 49 条：*修理型任务取证先行；病因假说仅为线索，施工先证实或证伪*。四条假说逐条查证结果如下。

### 病症一假说：「卡上当天唯一具体的信息就是那条事件文案」

**判定：主体成立，但表述需要修正——不是"唯一具体"，而是"唯一带戏剧性的具体"。**

取证方式：用 `tools/voice-check/collect_diary.cjs` 抽生产 `agentCard` 源码求值，打印真卡（下文第五章附全文）。逐字段清点：

| 卡上字段 | 具不具体 | 有没有"戏" |
|---|---|---|
| 特质／心愿／担忧／钱包／饥饿体力／正在做 | 泛化 | 无 |
| 最近（近 3 条日志正文） | 具体但是**事件词**（"回到工位""回卧室小憩"） | 无 |
| 今日片段（近 4 条正文+独白） | 具体，是**模板独白**（"把周报的字体调了十分钟"） | 弱 |
| **今天心里压着的事（v28 事件原文）** | **具体，且是唯一一句有因果、有对手、有情绪落点的话** | **强** |

所以修正后的机理是：卡上具体信息不止一条，但**只有事件文案是一句"可以直接当日记素材用"的完整叙事**，其余全是活动流水。模型要写"允许小情绪和具体细节"的日记，这句是唯一现成的抓手。

**由此确认两件事**（这两条决定了治法选型）：

1. **加强禁令措辞治不好**。v28 的禁令已经写到"不许直接提起它，更不许解释自己为什么这样"这个强度，仍被逐字搬走。再加措辞是同一条路上再走一步。
2. **降低注入强度也治不好**。降低强度＝减少模型能说的东西，抓手反而更稀缺。

反过来，**拿掉事件原文之后日记不会写空**——今日片段与最近仍在卡上，模板独白池本身就是具体生活细节（"闹钟定了四十分钟，信不过自己"）。这是治法可行的前提，一并证实。

### 病症二假说：招牌起手式失控

**判定：成立，且病根比"配额没管住"更靠前——现有机制里根本没有任何一处在管"语气词起手"。**

查证：`ZHAO_EVERY=5` 管的是"招牌起手式"这个**类目**的发放，判据落在 `AI_VOICE` 卡上对招牌的**语义定义**（沈小满＝感官招呼）。而"欸"是**语气词**，不是招牌类目——`欸你说这都几点了` 里"这都几点了"是抱怨吐槽，不是感官招呼，配额一侧看不出任何异常。所以：

- 决策者截到的三段里，只有第三段「欸你闻见没」踩了招牌定义；前两段「欸你说这都几点了」「欸你阳台那盆薄荷」是**合规产出**——它们连招的是"欸"，不是招牌。
- 换句话说，**v28 对"连续用同一个字起手"这件事零管辖**。这解释了为什么配额在、教训写死了、仍然连着三段"欸"。

**并同时证实：禁词表已经被绕过两次**，第 13 单点名「你闻见没」→ 模型换成「欸你看见…没」；v28 直接退回原句。故本单判据只能改结构。

### 病症三假说：「代码只派怎么开口，不派聊什么」

**判定：完全成立，代码层可直接对账。**

`enhanceChat` 的提示词里与话题相关的只有一句：

> 话题避开两人"最近"里已出现过的内容，聊当下场景或时段里的新鲜小事。

这是一句**否定式约束**（避开什么），不含任何正面指派。`styleAssign` 派的是开场类目（怎么开口），与话题正交。所以话题 100% 归模型自选——而模型在"合租公寓+当下场景"的约束下，收敛到冰箱是必然的：冰箱是这个场景里道具密度最高、最容易生出"新鲜小事"的物件。

**跨天事实矛盾（同一盒酸奶 D26 扔空瓶 → D27 过期两天 → 当晚还喝不喝）是同一个病根的下游症状**：模型没有物件级记忆，同一物件被反复选中就必然自相矛盾。派话题不能给模型记忆，但能把同一物件的复现频率压下去，矛盾自然稀释。

### 病症四假说：「日记与闲聊共用同一套语气/派活规则」

**判定：成立，而且是四条里唯一能在代码里指着一行说"就是这儿"的。**

`agentCard(ag,'diary')` → `styleAssign(ag,'diary')` → 从 `OPEN_KINDS` 里派类目。而 `OPEN_KINDS` 四类是：

```
['直接说事','抱怨吐槽','直接问对方','接对方上次的话往下聊']
                        ^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^
                        这两类本身就是对话指令
```

**v28 的实际行为是：代码有 50% 的概率在命令模型把日记写成对话。** 第五章附的 v28 真卡里就抓到现行：

- `a4 白一鸣 …｜本次开场必须用【直接问对方】这一类` —— 这是日记挂点。
- `a1 顾云帆 …｜本次开场必须用【接对方上次的话往下聊】这一类` —— 也是日记挂点。

对上决策者的两段实证，一一咬合：

| 实证 | 对应的代码指令 |
|---|---|
| 沈小满「…你明早去公司吗？帮我带…呗，我请。」 | 【直接问对方】 |
| 陆知秋「你刚才说散步到第三个路口才想起没带钥匙…」 | 【接对方上次的话往下聊】 |

**任务书说"后者更严重"，取证结果支持这个判断，并且能补上最后一环**：「走到第三个路口才想起没带钥匙，还好门没锁」是 `STROLL_THOUGHTS` 池里的**模板独白原文**（第 520 行）。它经"今日片段"上卡，模型收到【接对方上次的话往下聊】的指令后，在卡上找"对方上次的话"——卡上唯一像"一句话"的就是这条独白，于是它被认领成了别人说的。**模型没有犯错，它精确执行了一条自相矛盾的指令。**

**第三处共犯**：沈小满的招牌起手式在 `AI_VOICE` 里的定义是"感官招呼（**拉对方**一起闻/听/看的起手）"——一个**按定义就是第二人称**的构造。每 5 次一轮的招牌许可打到日记挂点上时，等于命令她在日记里对人说话。

## 二、治法与落点（逐条）

### 病症一 · 卡上给标签，不给事件

**改动**（DOM 层 AI 模块）：

```js
const SIT_MOOD={good:'今天挺顺', bad:'今天不太顺', flat:'今天平平淡淡'};   // 可调
```

`agentCard` 那一行由注入 `sit.text` 改为注入 `SIT_MOOD[sit.k]`。逐字对照：

```
v28：｜今天心里压着的事:被组长在群里点名夸了一句（这是背景底色，只影响你的语气和你挑什么说；不许直接提起它，更不许解释自己为什么这样）
v29：｜今天的心境:今天挺顺（这只定语气，不是内容：不许把这句话写进你说的话或写的字里，也不许解释自己今天为什么这样）
```

三档全形态（同一人同一时刻只换档位，机器实测）：

```
good → ｜今天的心境:今天挺顺（这只定语气，不是内容：…）
bad  → ｜今天的心境:今天不太顺（这只定语气，不是内容：…）
flat → ｜今天的心境:今天平平淡淡（这只定语气，不是内容：…）
无处境 / 已过期 / 篡改档档位不明 → 整行省略
```

口径：
- `ag.sit.text` **仍留在世界状态里**（随存档序列化，后续日报／剪辑要用），只是不喂 AI。
- `PEER_EVENTS` 事件表内容**一字未改**（硬口径 1）。
- 档位不明（篡改档写了个不存在的 k）→ 整行省略，不注入空标签。

### 病症二 · 语气词起手结构闸（方案乙启用）

**判据改结构，不改禁词**——禁词表已实证两次可绕过，故本闸只看"是不是拿语气词起手"，不看后面接的是哪个短语；换词、换动词、换语气词一律照拦。

```js
// 可调：语气词起手表。条目可为一字或两字——「哈」单字会误伤哈尔滨/哈欠/哈密瓜一类实词，
// 故只收「哈哈」；其余各字词首除语气词外无常用实词，单字即可判。
const LEAD_INTERJ=['欸','诶','哎','唉','呀','哟','嘿','嗨','咦','哦','噢','喔','嗯','啊','呃','哈哈'];
const LEAD_SCAN=10;   // 可调：只看开场前 10 个字符
```

流程：**剥掉开头的引号／括号／空白 → 取前 10 字 → 前缀命中语气词表即判不合格 → 由代码指定另一类开场（走现有 `OPEN_KINDS`／日记走 `DIARY_OPEN_KINDS`）重生成一次 → 至多一次，第二版仍不合格也照收。**

覆盖三个挂点：短信回信、同屋对白（A、B 两侧第一句都查）、睡前日记（谁不合格重开谁，合格的沿用第一版）。

约束照办：
- 至多一次；失败（重生成回包为 null）即沿用第一版。
- 受 `AI_TIMEOUT` 约束（走同一条 `callClaude` 链，死线不变）。
- **绝不阻塞日志墙**：模板句在 SIM 落条目时就已上墙，AI 文案本来就是"迟到原位补"，重生成只是让这次补写晚一轮。
- `ZHAO_EVERY` 配额原样保留，本闸是配额之外的兜底。

误伤自查（机器实测，全绿）：`你闻见没`（不带语气词的招牌，放行——招牌归配额管）、`跑通了，收工。`、`3% 的概率而已。`、`今天欸了一声，没人理。`（语气词在句中，放行——人味留着）、`哈尔滨的雪。`（实词，放行）。

### 病症三 · 话题由代码派

**新增 `TOPIC_POOL`（9 类，SIM 块）**——写到"地点／事由"粒度即止，不写到具体物件，留足发挥空间：

```
厨房与吃食 / 阳台与晾晒 / 楼道与门口 / 楼下街面（小店／摊子／路口） /
天气与季节 / 各自的工作 / 钱与开销 / 作息与睡眠 / 邻居与楼里的人
```

**频次过滤**：`TOPIC_RECENT=4`（可调，建议 4–5）——全城最近 4 次派过的类不再派，撞上则顺延（照 `styleAssign` 撞类顺延先例）。记账挂 `w.chatTopics`（全城一本账，照 `w.saidDay` 先例），随存档序列化，旧档缺省从空账起。

### 病症四 · 日记挂点收紧（代码两道 + 提示词一道）

任务书写的是"日记挂点单独收紧提示词"。**但只加提示词条款会直接违反本单铁律**——机理已证实代码正在派【直接问对方】给日记；如果只在提示词里写"不得提问"，就是让模型自己去调和两条打架的指令。这正是 `styleAssign` 函数里既有注释记着的坑（*"否则两条指令打架，实测有角色因此弃用派定类目改走招牌"*）。故先由代码掐掉冲突源，再写条款：

**代码第一道 · 日记专用开场池**

```js
const DIARY_OPEN_KINDS=['直接说事','抱怨吐槽','从今天的一个具体画面写起','从此刻身上的感觉写起'];
```

四类全是"写给自己"的起手，一个都不带第二人称／提问／承接他人话语。**数量与 `OPEN_KINDS` 同为 4**，保住日记提示词"四段必须风格迥异"赖以成立的四人四类分配前提。`OPEN_KINDS`（对白／短信用）**一字未改**。

实测连续 8 轮（四人四类，无相邻同类）：

```
轮次 | 顾云帆（日记）        | 沈小满（日记）        | 陆知秋（日记）        | 白一鸣（日记）
 1  | 从此刻身上的感觉写起  | 直接说事              | 抱怨吐槽              | 从今天的一个具体画面写起
 2  | 直接说事              | 抱怨吐槽              | 从今天的一个具体画面写起 | 从此刻身上的感觉写起
 3  | 抱怨吐槽              | 从今天的一个具体画面写起 | 从此刻身上的感觉写起  | 直接说事
 4  | 从今天的一个具体画面写起 | 从此刻身上的感觉写起  | 直接说事              | 抱怨吐槽
（5–8 轮循环同上）
```

对白挂点同轮对照（回归，四类与招牌配额原样）：

```
 1  | 接对方上次的话往下聊 | 直接说事 | 抱怨吐槽 | 直接问对方
 2  | ★招牌 | ★招牌 | ★招牌 | ★招牌
 3  | 抱怨吐槽 | 直接问对方 | 接对方上次的话往下聊 | 直接说事
```

**代码第二道 · 日记不发招牌许可**

招牌是"起手**式**"＝开口跟人说话的套路，日记不是开口；且沈小满的招牌按定义就是第二人称构造，与本单硬条款正面冲突。故 `styleAssign` 的 diary 分支不发招牌许可，改发：

> 本次不要用你的招牌起手式——招牌起手式是开口跟人说话的套路，日记是写给自己的。

`aiTurn` 计数照旧递增，短信／对白挂点的招牌节律**不受影响**（160 次派活中仍发放 32 次＝1/5，节律未变）。

**提示词一道 · 日记体铁律五条**（写死在 `runReflection`，全文见第五章）

> 日记体铁律（五条，写完逐条自查，违反任何一条即为不合格）：①这段字只写给自己看，不是说给任何人听；②通篇不得出现第二人称（你／你们／您／咱），也不得称呼任何人；③不得提问，全段不出现问号；④不得复述别人说过的话，也不得把角色卡"今日片段""最近""上次开口"里的句子当成别人对你说的话——那些全是你自己心里的话和自己做过的事；⑤不得出现对白结构（引号包住的整句对话、"我说…TA说…"、破折号领起的话轮）。

第 ④ 条专门点破"今日片段是自己的心里话"——因为决策者实证里最重的那一段（陆知秋把 STROLL 模板独白当成别人说的话）正是栽在这里。

2. **日记挂点的明喻配额节律有极轻微变化**：`simile` 判据是 `n%3===0 && !zhao`；日记不再发 `zhao`，故第 15、30…轮（`n%15===0`）在日记上由"两项都不发"变成"发明喻许可"。属配额落点的算术副作用，不改变每 3 次一发的节律。
3. **同一话题仍可跨窗口复现**：`TOPIC_RECENT=4` 只保证最近 4 次不复读，不做更长窗口去重（照 `PEER_EVENTS` 已登记的同款接受项）。30 天实测最集中一类占 13.7%。
4. **物件级矛盾未根治**：派话题只压低同一物件的复现频率，不给模型物件记忆。彻底解决要等"周记忆压缩"（待办·目标系统·换脑）。
5. **`TOPIC_POOL` 未覆盖的场景一律不聊**：例如"手机/网购/追剧"不在 9 类里。这是刻意的——池子越大频次过滤越弱。要加类直接说。
