# 第 196 单 · 出包链第四道闸：APK 内嵌页逐字节核对 —— 不涨号·仍 v155

> 一句话：前三道闸守的是"链上各步"（升级号／www 镜像／cap sync 拷贝），而**最后装进 APK 的
> 那份页面**一直没有机器核对——第 194 单把它照实登记成缺口。本单补上：出包后把 APK 里的
> `assets/public/index.html` 用 JDK 自带 `jar xf` 解出来，与 `www/index.html` **逐字节**比对，
> 不一致就**拒绝出包**。

## 一 · 四道闸各管一段

| 闸 | 管哪一段 | 何时立 |
|---|---|---|

| `apk/www` 镜像同步（流程） | 壳里的 www 停在旧版（曾停 v152） | 第 189 单顺带 |
| cap sync 拷贝校验 | 暂存目录 `android/.../assets/public/` | 第 194 单 |
| **APK 内嵌页核对（本单）** | **最终产物里那份页面** | 第 196 单 |

## 二 · 改了什么

- 新增 `apk/check-embedded.cjs`：`jar xf <apk> assets/public/index.html` → 解到
  `out\verify\`（F 盘、纯 ASCII 路径；**核对完即删**）→ 与 `www/index.html` 逐字节比对；
  缺 `jar.exe`／APK 里缺页／不一致 → 退出码 1（打印两边字节数与 sha256 前 12 位）。
  依赖只用 **JDK 自带的 `jar`**（零新依赖）。
- `apk/build-apk.bat`：加 `[6/6] verify the packaged page matches the game`。
- `.bat` 合规复核：**CRLF 41／裸 LF 0／非 ASCII 0**。
