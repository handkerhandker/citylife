# 第 155 单 · 性能探针（帧时统计，首个）——不涨号·仍 v126

> 一句话：本项目从未量过"每帧要花多久"，而 139/148/152 等单一直在往每帧里加绘制——
> 本单立**性能探针**：四个最重场景各跑 8 秒 rAF，量帧间隔分布与长帧。**首测全绿**：
> 四场景 p50 8.3ms、p95 8.8ms、长帧 0（烟花/挖空/雨幕都没有压出卡顿）；
> 反向自查（把 rAF 每帧压 30ms）p50 冲到 60.7ms——判据不是恒绿。

## 一 · 口径

- 工具：`tools/perf-audit/probe.mjs`（档 2；`--改前` 可对旧版跑同口径）。
- 四场景（同 seed、1.5 秒起摆余波后测 8 秒、丢头 2 帧）：
  ① 白天（12:30）② 夜晚（03:00）③ 雨夜（23:00，雨幕全开）④ 节日夜＋烟花＋选中者气泡。
- 读数：p50 / p95 / p99 / max / 长帧（>100ms）数。
- 判据（宽松、与机器无关的"卡死级"）：**长帧总数 ≤2 且 p95 ≤22ms（≈掉到 45fps 以下才红）
  且反向自查通过**（人为拖慢必须判红）——不拿绝对帧时卡机器差异，抓"某改动把每帧拖垮"。
