# 第 87 单 · 回礼（收了人家的东西，隔几天回一份）

> 一句话：第 81 单让邻居在生日那天**带点东西来**，收下就完了；本单把这条线接成**双向的**——
> 收礼的人把这份人情**记在自己身上**（`ag.giftRecv`），隔 **3–13 天**、同样 **15:00–21:00**、
> 同样要**当面**（同屋）才回一份，回礼比原礼轻一点（**−¥6**）；**过了 13 天没回上就作废**（不无限期惦记）。
> 两条日志（回的人"回了…"／收的人"收下了…回的…"）＋ 回礼那句进既有的 `gift` 剪辑类（覆盖率照旧）。
> 指纹：**只有 SIM 块 md5 变**（`53f6e853…` → **`2c64d522…`**），世界 `b5935386…` 与门禁 `d759a1f6…` **逐字节原样**
> （礼物只发生在生日当天、生日最早在 D72，回礼还要再隔 3 天——两个指纹只看头 30 天，窗口走不到）。版本：v81 → **v82**。

## 一 · 缘由与出处

第 81 单交付时登记过第 3 条接受项："**送过礼不会有回礼**（回礼属另一单）"——本单就是那一单。
同类作品的出处沿用第 81 单那两条（`docs/规划/借鉴调研-2026-10-03.md`），不另编新出处：

| 出处 | 抄到的口径 | 本单落成 |
|---|---|---|
| 星露谷 wiki·Friendship（2026-10-03 实测 HTTP 200） | 「villagers are more likely to **send gifts** in the mail」——关系深浅会改变**对方怎么对待你** | 收到的礼要**还一份**（关系不是单向的"收"） |
| Nookipedia·Friendship（2026-10-03 实测 HTTP 200） | 友谊是**互动**（interaction）、「**+1 point — speaking to the villager for the first time each day**」（一天一次、防刷） | 一笔人情**只回一次**（回完即清），且**记的是"一份"而不是"一件"** |

## 二 · 设计

```js
const GIFT={ cost:8, back:6, open:15*60, close:21*60, thing:'一小盒点心',
             backMin:3*1440, backMax:13*1440 };
// 收到礼时（第 81 单那两条日志之后）——把人情记在**收礼人**身上：
if(寿星) 寿星.giftRecv={ t:w.t, from:ag.id, fromName:ag.name };

// decide() 礼物窗口里，回礼分支排在**送新礼之前**（欠着的人情优先）：
if(ag.giftRecv && ...){
  const 隔=w.t-ag.giftRecv.t;
  if(隔>=GIFT.backMax) delete ag.giftRecv;                    // 过期作废
  else if(隔>=GIFT.backMin && 对方同屋 && 对方空闲){
    const 欠=ag.giftRecv; delete ag.giftRecv; ag.money-=GIFT.back;
    const 句='回了'+GIFT.thing+'给'+欠.fromName;
    ag.lastGift={ t:w.t, to:欠.from, toName:欠.fromName, spent:GIFT.back, tx:句+'（¥'+GIFT.back+'）' };
    logAct(w,ag,句,'上次人家带了东西来，总得还一份。');
    logAct(w,收,'收下了'+ag.name+'回的'+GIFT.thing,'（这人客气。）');
    return;
  }
}
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| **3–13 天** | `backMin=3*1440`／`backMax=13*1440` | 太早显得急、太晚不像还；两天缓冲足够走过一个周末 |
| **过期作废** | `隔>=backMax` ⇒ `delete ag.giftRecv` | **不无限期惦记**——忘掉一笔旧人情比"三年后突然还礼"自然 |
| **还是当面** | 同 `roomOf(收.anchor)===roomOf(ag.anchor)` ＋ 对方 `idle`／`stroll` | 与第 81 单同一条口径：东西要真递到手上 |
| **回礼更轻** | `back:6`＜`cost:8` | "还礼"不比原礼重，也不等于把东西退回去 |
| **$在收礼人身上** | `寿星.giftRecv=…` | 欠人情的是**收**的人；记在送礼人身上就成了"我送过谁、TA 欠我"——那是另一套账 |
| **一天一份** | 一笔账只存 `{t,from,fromName}` | 一天收到多份只记**最后一份**（见第七节接受项） |
| **排在新礼之前** | 回礼分支在 `ag.giftYear!==年` 那段**之前** | 欠着的人情优先——同一天窗口里不会"先去送新的、旧的不理" |
| **归类** | `CLIP_LOGCAT` 新增 `['gift',['回了']]` | 与前缀写法配对（写成"给‹名字›回了…"前缀会随名字变）；不动既有那条是怕动到既有断言 |

## 七 · 已知接受项与盲区（照实登记，不粉饰）

1. **一天里收到多份，只记最后一份**（`giftRecv` 是个单值，不是队列）——生日那天被三位邻居各送一份，
   他只欠最后那位一份。要改就得把 `giftRecv` 变成数组，属另一单。
2. **回礼只有一种东西**（还是那盒点心）：没有偏好、没有"按关系深浅选轻重"（后者要先有关系数值，
   属关系状态机那单）。
3. **没有"回谢玩家"**：欠账只记住户之间的礼；玩家送的祝福（短信）不进这套账。
4. **回礼不是"必须"**：3 天没碰上（不同屋／对方一直在忙）就一直等到第 13 天，然后作废——**漏掉是设计的一部分**。
5. **回礼当天不再送新礼**：回礼分支 `return` 掉了，同一天窗口里不会再给别人送生日礼物（一天一件事）。
