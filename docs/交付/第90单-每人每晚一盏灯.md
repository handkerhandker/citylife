# 第 90 单 · 江灯节「每人每晚一盏」（治第 62 单登记的那条接受项）

> 一句话：江灯节那一晚（19:00–23:00）原来**反复去**——实测一晚 **11–12 盏来自 4 个人**（顾云帆／陆知秋各 4 盏），
> "一年一次"的日子读起来反而像在刷。本单给每人加一道**今晚放过没有**的判据（按 `PURE.dayOf` 记日）：
> 放过就不再去了。现在一晚**恰好 4 盏、每人一盏**，收灯播报也跟着报 4。
> **那次抽签一个字节没动**（判据排在小括号之后），故 rng 流不位移、两枚指纹与本单无关地不动。
> 版本：v83 → **v84**。指纹：世界 `b5935386…` 与门禁 `d759a1f6…` **原样**，SIM 块 md5 `dce40e25…` → **`212f0607…`**。

## 二 · 设计

```js
if(inFestival(w) && (ag.flags.wantFest || w.rng()<Math.min(0.98,FESTIVAL.p+goalKnob(ag,'fest')))){
  delete ag.flags.wantFest;
  if(ag.festLampDay===PURE.dayOf(w.t)) return;      // 第 90 单：今晚放过了 ⇒ 不再去
  ag.festLampDay=PURE.dayOf(w.t);
  w.festCount=(w.festCount|0)+1;
  …（放灯：−¥5、`setActivity` 走江边、日志原文）
}
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| **判据位置** | 写在那次 `w.rng()` **之后** | rng 调用位置一个字没动 ⇒ 六项读数与两枚指纹据此不变（要改的是"去不去"，不是"摇不摇"） |
| **按日记** | `ag.festLampDay`＝`PURE.dayOf(w.t)` | 节日只有一晚（19:00–23:00），记日号就够；跨年自动作废（日号只会往前） |
| **跳过 ≠ 停摆** | `return` 只表示"这一拍不去" | 他留在原地、下一拍重新决策；上班／吃饭／睡觉那几支一概不碰 |
| **播报对账** | 收灯那句读的还是 `w.festCount` | 一晚上限 4 盏是"每人一盏"的直接后果，播报不用另算 |
| **一年一次** | `ag.festYear` 那条**没动** | 剪辑层 `fest_lamp`（每人每年至多一条）照旧 |

## 七 · 已知接受项

1. **一晚至多 4 盏**（每人一盏）——若某人在上班／吃饭／睡觉，可能一盏都不放；第 62 单那条"当晚 ≥2 盏"的门槛照旧成立
   （实测三颗种子恒为 4）。
2. **`fest` 旋钮的差别变小了**：原来"多去几趟"能把差别放大，现在四个人一晚各一盏，旋钮只影响**谁去得早／去不去**。
   这与待办里那句"治成每人一盏后，旋钮在整晚尺度上才量得出差别"是同一件事的两面——要不要重新定标，另立单。
3. **跳过那一拍不做事**：他留在原地（等同于"今晚不去了"），下一拍照常参与其它决策；这是"去重"最省的做法。
