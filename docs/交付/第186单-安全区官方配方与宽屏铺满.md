# 第 186 单 · 安全区取数（Capacitor 官方配方）＋ 宽屏铺满（两条真机反馈）——v151 → **v152**

> 决策者两条真机反馈：① **竖屏顶栏（地点/时间/钱/按钮）被系统状态栏盖住**；
> ② **横屏下侧/左侧/上侧是空白深色区、游戏画面没铺到**。
> 这次**先去搜现成案例**（决策者点名要求），拿到 Capacitor 官方口径后照做——
> ① 用平台注入的 `--safe-area-inset-*`（回落 `env()`）；② 宽屏按"铺满宽度"取缩放。

## 一 · 出处（本轮现查，2026-10-04 实测 HTTP 200）

**Capacitor 官方 SystemBars 文档**：<https://capacitorjs.com/docs/apis/system-bars>

> "Due to a bug in some older versions of Android WebView (**< 140**), correct safe area values
> are **not available via the `safe-area-inset-x` CSS env variables**. This plugin will inject the
> correct inset values into a new CSS variable(s) named `--safe-area-inset-x` that you can use as a
> fallback in your frontend styles:
> `html { padding-top: var(--safe-area-inset-top, env(safe-area-inset-top, 0px)); … }`"
> "To control this behavior, use the **`insetsHandling`** configuration setting."

**同题材的社区实现**（Capacitor 团队的修复 PR 正是照它做的）：
`@capacitor-community/safe-area` README —— "On Android … those CSS variables will not always have
the correct values when Edge-to-Edge mode is enabled"，低于 Chromium 140 的 WebView 里
`env(safe-area-inset-*)` 就是 `0px`。

**同题材的上游 issue**（都能对上我们的症状）：
- ionic-team/capacitor **#8623**（open）：8.5.2 里 SystemBars 会在"没有 edge-to-edge"时也注入非零值；
- **#8636**（open PR）：注入时机太早（`document.documentElement` 还没建好）会抛错 ⇒ 平台值可能缺一拍；
- **#8384**（closed）："use native safe area insets on Android"（社区插件那套做法进了核心）；
- Stack Overflow **52476016**（score 12）："`env(safe-area-inset-top)` not working on Android Pie + WebView 69"。

> 一句话：**安卓 WebView 里 `env(safe-area-inset-*)` 靠不住**——这正是 ① 的根因（页面没内缩、顶栏钻到状态栏底下）。

## 二 · 改了什么

### ① 安全区取数（照官方配方）

- 页面四轴改成**先读平台变量、再回落 env()**：
  `--sa-t:var(--safe-area-inset-top, env(safe-area-inset-top, 0px));`（b/l/r 同理）；
- `apk/capacitor.config.json` 增 `plugins.SystemBars.insetsHandling="css"`（让平台把值注入成 CSS 变量，
  而不是用 padding 顶开 WebView——后者会把"铺满"毁掉）；
- 安卓壳只做**兜底**：平台变量某轴缺失（空或 0px）时才自补 `--sa-*`，**不跟平台抢值**
  （上游 #8636 那种"注入早于文档"的一拍，由这条兜住）。
  同时修掉上一版"两条腿"判据在卓易通上的**误伤**：顶部不再用 `isVisible()` 清零
  （宿主的系统栏不是安卓画的那条，系统报"不可见"⇒ 清零 ⇒ 顶栏被盖；横屏那条假值仍由
  "横屏强制 top=0"兜住）。

### ② 宽屏铺满

画布比地图更"宽"（手机横屏、平板）时，缩放改取**铺满宽度**（`w/MAPW`）：
地图横向铺满、纵向按需裁切（镜头跟随/手动平移照旧）；竖屏（画布比地图窄）仍走原来的
"整幅能看清"，行为不变。
