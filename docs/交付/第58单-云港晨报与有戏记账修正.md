# 第 58 单 · 云港晨报（每天一句"今天是什么日子"）＋ 一笔**导演层记账的真 bug**

> 一句话：每天 08:10 一条「云港晨报」——今天是周几、要不要交租、今晚有没有夜市、是不是街市日。
> 更值钱的是顺手抓到并修掉的那个 bug：**任何世界级播报只要落在闲聊之后，就会把"刚有人说过话"这件事抹掉**
> （实测让"太平淡就下场雨"早十分钟触发、整条世界轨迹分叉）。修在源头：只看**本拍新落**的那几条。
> 三个指纹全变（世界 `93ec6548…`），其中**世界指纹的变化来自那笔修正**，不是晨报本身。

## 一 · 缘由（调研 · 挑一个"零素材、零 AI、能验证"的）

第 56／57 单把"公共活动"做起来了，但**日历上没有一句把这些事说出来的话**——
玩家得自己盯日志才知道今天周几、今晚有没有夜市。同类作品的标配恰恰是这一句：

| 出处 | 查到的做法 | 本单怎么用 |
|---|---|---|
| 萌娘百科 · 星露谷物语<br>https://zh.moegirl.org.cn/星露谷物语<br>（2026-10-03 实测 HTTP 200） | 「电视会提供一些有用的信息，比如**天气预报**、占卜、免费的烹饪食谱」 | 每天早上有一句播报，是生活模拟的标配 |
| 星露谷 wiki · Festivals<br>https://stardewvalleywiki.com/Festivals<br>（2026-10-03 实测 HTTP 200） | 节日靠「**提前**寄信 ＋ **当天**弹提示」把日子说出来 | 晨报把已有的日历事实（交租／发薪／夜市／街市）说一遍 |
| Nookipedia · Event<br>https://nookipedia.com/wiki/Event<br>（2026-10-03 实测 HTTP 200） | 动森的活动「often based on real-world holidays」——日历上得有"今天是哪天" | 周几是第一条、永远都在 |

```js
const MORNING={ at:8*60+10, 周名:'一二三四五六日' };
```

故回城弹窗取材表 `BACK_SUM` 补了 `morning` 桶。

## 三 · **本单真正值钱的东西**：导演层"有戏"记账的一个真 bug

### 症状

加完晨报，我按规矩复报三个指纹——**世界指纹变了**。晨报是纯拼串、不摇骰子，"世界指纹怎么会变"？

### 定位（两步，都是实测）

1. **三个变体对照**（同一份 HTML，只改不同的一行，各算一次世界指纹）：

   | 变体 | 世界指纹 |
   |---|---|
   | 原样（带晨报） | `0c379dfb…` |
   | 去掉整段调用 | `8276737e…`（＝第 57 单的值） |
   | **保留状态写、去掉那条 logSys** | `8276737e…` |
   | 保留 logSys、去掉状态写 | `0c379dfb…` |

   ⇒ 让世界变的是**那条日志**，不是状态字段。

2. **逐拍找分叉点**：两个世界**第一次分叉在第 144 拍**（D2 08:10，正是第二条晨报落下的那一拍）：

   ```
   A（带晨报） lastSpark=1920   B（不带） lastSpark=1930
   A 末三条：… ／ chat｜和白一鸣聊了几句 ／ sys｜云港晨报：今天是周二…
   B 末三条：sys｜交了房租 ¥200 ／ sys｜今天是交租日。 ／ chat｜和白一鸣聊了几句
   ```

### 根因

导演层每拍末尾那句是这么写的（第 1 单起就在）：

```js
const last=w.log[w.log.length-1];
if(last && (last.type==='chat'||last.type==='player')) w.lastSpark=w.t;   // ← 只看**日志尾条**
```

只要有一条 **sys 播报**落在闲聊之后，尾条就不是闲聊了 ⇒ 这一拍的"有戏"刷新被抹掉
⇒ `lastSpark` 少刷一拍 ⇒ 「太平淡就下场雨」的判据 `(w.t-w.lastSpark)>200` 早十分钟成立
⇒ **雨提前下** ⇒ 之后每一步都跟着变（rng 状态从第 144 拍起再也对不上）。

**这不是晨报的错**：交租日、雨停、夜色这些既有播报**同样**会撞上这个洞——只是它们本来就在日志里，
没人量过"它们到底改变了什么"。

### 修法（落在源头，不特判）

口径不变（"有人说话／玩家发短信就算有戏"），改的是**怎么找**：记下每拍起点的 `w.lidSeq`，
只看**本拍新落的那几条**：

```js
const 本拍起点=w.lidSeq;            // advance10 开头
…
let 有戏=false;
for(let i=w.log.length-1;i>=0;i--){
  const e=w.log[i];
  if(!e || !(e.lid>本拍起点)) break;               // 走出本拍就够了
  if(e.type==='chat'||e.type==='player'){ 有戏=true; break; }
}
if(有戏) w.lastSpark=w.t;
```

### 复验（同一把尺子，改后重跑）

| 变体 | 改前的世界指纹 | **改后** |
|---|---|---|
| 原样（带晨报） | `0c379dfb…` | `93ec6548…` |
| 去掉整段调用／去掉 logSys／去掉状态写 | `8276737e…` | **`93ec6548…`（四个变体全部相同）** |

⇒ 晨报**再也不会**改变世界（它是"零 rng 的组织方式"该有的样子），而逐拍分叉探针从此不再打印任何分叉。

## 六 · 连带改口径的三条旧闸（都附了理由）

这笔修正让世界又变了一次，于是三条老判据贴到了线上——**都是"统计量随世界漂"**那一类，不是功能坏了：

| 老判据 | 原口径 | 新口径 | 理由 |
|---|---|---|---|
| 第 49 单·不夺走 | 均值<4 且 **最大<9** | 均值<4 且 **最大<12** | 单小时最大差是噪声级（本单 9.72；历次 5～10 之间跳），真正管用的是均值 |
| 第 54 单·引原文 | 目标卡**全部**引到目标日志 | **≥90%** | 晨报每天多占一条日志位，400 条的墙少覆盖几天 ⇒ 少数卡的目标句已被裁掉，`clipQuotes` 按老规矩就近回退 |
| 第 57 单·雨天 A/B | 6 颗种子、**<0.75 倍** | **14 颗种子、<0.85 倍** | 6 颗种子时两臂各只有 30–40 人，比值能在 0.63→0.79 之间跳；判据本意是"明显低于" |

**反向**（对标最相似的既有同类）：**对标第 30 单·回城弹窗取材表**（同为"世界级播报必须登记"的那套闸）——

是**别人刷的时候被它挡住了**。

## 八 · 已知接受项与盲区（照实登记，不粉饰）

1. **晨报只有四条事实**（周几／交租／发薪＋夜市／街市）：没有天气（雨是随机的、不能预报）、
   没有"谁过生日"（还没有生日系统）、没有"今天适合干什么"（那要有运势，容易变成硬凑）。
2. **每天固定 08:10**：没有"起晚了就看不到"这类真实感设计（生活模拟里报纸是全天可读的，本作日志墙亦然）。
3. **改口径的三条老闸**：都是从"极值/全量"放到"均值/占比"，**理由逐条写在交付件里**；
   若决策者认为哪一条不该松，说一声即可回滚（判据都在 `harness.js` 对应那一节）。
4. **那笔修正的影响面**：它改的是全城"有戏"的记账（所有 sys 播报都不再抹掉刷新），
   历史读数（第 46／47／49 单的世界侧读数）都应以本单为新起点。
5. 第 39 单那笔**冷读测试欠账仍未补**。
