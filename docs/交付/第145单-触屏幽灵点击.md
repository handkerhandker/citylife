# 第 145 单 · 触屏点选的"幽灵点击"（修复）——v120 → **v121**

> 一句话：补最后一块没测过的交互表面（**触屏**），首跑就抓到实伤——**手机上点小人，角色卡一闪即没**。
> 根因：pointerup 弹卡后，浏览器还会按"点击时刻"做一次合成 click 的命中测试，落点已被刚铺开的
> 卡片背景（`.dlg-backdrop`）盖住 ⇒ 这次 click 把卡当"点背景"当场关掉。修复：**触摸路径弹卡时记时间戳，
> 捕获段吞掉 450ms 内的下一次 click**（只对 touch 记录，桌面零影响）。

## 一 · 现场与根因（事件轨迹，触屏探针实测）

```
[ 'down', 'touch', 104, 466 ]       ← 手指按下
[ 'mut', 'open', 1142 ]             ← pointerup：卡片弹出（开）
[ 'up', 'touch', 104, 466 ]
[ 'docClick', 'dlg-backdrop' ]      ← 浏览器合成 click，命中测试落在刚铺开的卡片背景上
[ 'mut', '', 0 ]                    ← 背景 click ⇒ closeDialog（卡片被关掉）
```

| 事实 | 说明 |
|---|---|
| 桌面为什么没事 | 鼠标没有"合成 click"这一层：pointerup 弹卡就是终点 |
| 影响面 | ① 点选换人（卡片打不开）；④ 小拖（≤8px）算点按——同样中招；拖拽平移等其余触屏路径正常 |
| 旧版可复现 | `node tools/touch-audit/probe.mjs <out> --改前=7b52c88` ⇒ **①④ 红、其余绿** |

## 二 · 修复（3 行口径，只动 DOM 层）

| 件 | 做法 |
|---|---|
| 记 | 画布 pointerup 选中并弹卡后，若 `e.pointerType==='touch'` ⇒ `吞点击=performance.now()` |
| 吞 | 文档**捕获段** click：若距 `吞点击` <450ms ⇒ `stopPropagation()+preventDefault()`（吞掉的就是那次合成 click） |
| 界 | 只对 touch 路径记录——**桌面点选行为零变化**（鼠标连点不会被吞） |

## 五 · 已知接受项

1. 吞击窗口 450ms 是拍的（一处可调）；无合成 click 的环境里，450ms 内的下一次真点击会被吞一次（代价：再点一下）。
2. 只测 Chromium 触摸仿真（与用户浏览器同内核）；真机（iOS Safari 等）未测——老账。
3. 触屏探针用的是"点按/拖拽"两类手势；双指捏合不测（`user-scalable=no`＋`touch-action:none` 双保险已禁缩放）。
