# 第 198 单 · 出包链四道闸"存在性上锁" —— 不涨号·仍 v155

> 一句话：今晚给 `apk/` 加的四道闸（升级号 191／www 镜像 189／cap sync 拷贝 194／APK 内嵌页 196）
> 都靠 `build-apk.bat` 串起来——但"**在不在、串没串**"此前没人管：一次重写就可能把某道闸静默拆掉。
> 本单把它们的**存在与串联**写进 harness（含反向自查）——照第 66 单"闸自己没人管"那条教训。

## 一 · 为什么要做

- 四道闸分布在 `apk/` 三个脚本 ＋ `build-apk.bat` 四处调用点上；**没有任何判据盯着它们还在不在**。
- 同型教训先例：第 66 单立"反向自查登记表"（防整条被删）、"工具登记表"（防新工具漏登记）。
  闸会被人（或未来的 AI）静默拆掉这件事，也是同一类病。

## 二 · 改了什么

- `harness.js` 新增第 198 单：
  - **2 条结构判据**：① 三个守卫脚本都在（`set-version.cjs`／`check-www-copy.cjs`／`check-embedded.cjs`）；
    ② 四道闸都串在 `build-apk.bat` 里（含出包后 aapt 复查 `versionCode='1'` 那一条）；
  - **1 条反向自查**：把"APK 内嵌页核对"从出包脚本里抠掉 ⇒ 结构判据当场判红；
- 反向自查登记表对齐：**108 组**。

## 四 · 双审计

**正向**：① 四道闸各有脚本与调用点，且全部在 git 里（可追溯）✓；② 反向自查不是"恒真"（真跑病态改写）✓。
**反向**（对标最相似的既有同类：**第 66 单·闸三 反向自查登记表** ＋ **工具登记表（第 83 单）**）逐点确认：
① 同型——"闸自己也要有人管"，用机器判据盯存在性 ✓；② 都**不锁版式**（判存在与串联，
不管注释/排版怎么变）——避免"闸咬版式" ✓。
