## 一 · 机理报告（取证先行，五问逐条）

取证脚本＝`tools/offline-catchup/probe.cjs`（诊断工具，不是门禁：不进 `gate.yml`、不判红、只印读数）。
复跑：先按门禁第 1 步抽出 `app.js`，再 `node tools/offline-catchup/probe.cjs`。

### 问 1 · 关掉页面／切走标签页，世界推进到底停不停？停在哪一步？

**停。停在 `requestAnimationFrame` 这一步，而且是干干净净地停。**

| 判据 | 读数（源码判读） |
|---|---|
| `Sim.step(` 全站调用点 | **1 处**，长在 `loop()` 里 |
| `loop()` 结尾自续 rAF | 是（`requestAnimationFrame(loop)`） |
| 单帧时间步封顶 | `dtFrame=Math.min(0.1,…)` 秒 ⇒ **一帧至多折算 1 模拟分钟 × 速度** |
| 离场落盘钩子 | `pagehide → saveNow()`；`visibilitychange(hidden) → saveNow()` |

- **切走标签页／最小化**：第 25 单已查到「整条 rAF 停」。本单把链条补完整——`Sim.step` 的**唯一**驱动就是 `loop()`，`loop()` 的唯一驱动就是 rAF，故 **rAF 停 ⇒ `Sim.step` 停 ⇒ 世界停**，不存在「渲染停了但世界还在走」的第二条路。
- **恢复时会不会自己追回来**？不会。浏览器恢复时补发的那记大 `dt` 被 `Math.min(0.1,…)` 削到 0.1 秒＝**1 模拟分钟**，而一拍需要攒够 10 分钟；离开一小时也只补得回 1 分钟里的零头。这条封顶是第 25 单情形②已立断言的那一条，本单只是指出它同时也堵死了「靠大 dt 自动追帧」这条路。
- **浏览器彻底关闭**：进程没了，什么都不跑。走的是 `pagehide`（Safari/iOS 走它，`beforeunload` 在移动端不可靠）与 `visibilitychange` 两个钩子落盘，两条都调既有的 `saveNow()`。**关页那一刻的世界是存住了的，只是从此不再前进。**

**⇒ 结论：本单要补的不是「世界跑飞了」，而是「世界压根没跑」。**

### 问 2 · 存档里存的是什么？`w.t` 随档落盘吗？重开是从存档继续还是从头？

**`w.t` 随档落盘，重开从存档的 `w.t` 继续，不是从头。`serialize`/`hydrate` 的逐字口径如下。**

```
存档顶层：{ sv: 1, meta: {...}, world: {...} }
meta 三键：selected / lastReflectDay / at        ← at 即「上次落盘的真实时刻」（Date.now()）
world 18 键：t / speed / agents / log / lidSeq / credits / sentToday / stats / weather /
             lastSpark / rentPaidDay / seed / rngState / saidDay / chatTopics / clips / clipBase / clipDay
```

- `serialize(w, meta)` 的口径是 **`for(const k in w)` 逐键拷贝，只跳过 `typeof==='function'`**。故 `w.t`、`w.rngState` 全都在档里，`w.rng`（闭包函数）不在。
- `hydrate(str)` 只做四件事：`JSON.parse` → 核 `sv===1` 与 `world` 存在 → 核 `isFinite(w.t)` 与 `agents` 是非空数组 → **按 `w.rngState` 重建 `w.rng` 闭包**。`rngState` 非有限时回落 `((w.seed>>>0)||1)`。
- 实测：落盘 `w.t=4800`（D4 08:00），`hydrate` 回来仍是 `4800`，**逐字节相同**。
- 存档体积：3 天 36,621 字节／30 天 85,516 字节（日志为 400 条环形缓冲，故不随天数无限长）。
- **关键结论**：「上次关闭的真实时刻」这个数**第 6 单起就一直在存**（`meta.at`），而且启动时已经被读出来用于「已存 · D4 08:00 · 3 天前」那一行。本单没有新增任何存档字段——**要的数早就在档里，只是从来没有人拿它去推世界。**

### 问 3 · 推进 N 拍的真实代价（关 AI、关渲染，纯世界逻辑）

`node v22.22.2 · linux/x64`，每档 7 次取中位；「②」一栏是**离线追帧的真实形态**（先 `hydrate` 一份跑满 30 天的存档，再往上推）。

| 天数 | 拍数 | ① 从零开城（中位，双种子） | ② 从 30 天存档 hydrate 后推进（中位／最坏，含 hydrate） |
|---:|---:|---|---|
| 1 | 144 | 0.6 ／ 1.0 ms | **1.8 ms** ／ 3.3 ms |
| 3 | 432 | 2.9 ／ 1.5 ms | **3.3 ms** ／ 9.6 ms |
| 7 | 1008 | 5.2 ／ 2.9 ms | **4.9 ms** ／ 9.1 ms |
| 30 | 4320 | 13.2 ／ 12.4 ms | **12.5 ms** ／ 16.0 ms |

（`hydrate` 单独：中位 0.53 ms。）

**这个数决定了本单的可行性判定：补算 30 天也就 12.5 毫秒，比一帧（16.7 ms）还短。**
故任务书第二优先档的触发条件（「若补算耗时不可接受」）**没有成立**。下面仍然设了封顶，但**理由不是成本**——理由见第二章。这一点必须说清楚，否则日后有人会以为封顶是性能妥协，进而随手放宽。

> 照实说明的两条边界：①上表是 node，手机浏览器上会更慢，但即便按 10 倍算，30 天也只有 0.13 秒；②表里是纯 `Sim.step`，本单实际的补算还多落了每晚 5 条模板日记条目，那是纯 `pushLog`，量级可忽略（30 天共 150 条）。

### 问 5 · `w.rng` 状态随档落盘吗？同一份存档推同样的拍数，结果逐字节可复现吗？

**落盘，且逐字节可复现。**

| 判据 | 20260803 | 424242 |
|---|---|---|
| 同一份存档各推 1 天 | 逐字节一致 ✓ | 逐字节一致 ✓ |
| 同一份存档各推 3 天 | 逐字节一致 ✓ | 逐字节一致 ✓ |
| 同一份存档各推 30 天 | 逐字节一致 ✓ | 逐字节一致 ✓ |
| 「存档往返再跑 3 天」对「原地直接跑 3 天」 | 逐字节一致 ✓（`rngState` 296925079） | 逐字节一致 ✓（`rngState` −1554477295） |

比对面不只是四个字段，而是 `t`／`rngState`／`stats`／`lidSeq`／**全部日志条目原文**／逐人九项／`clips`／`saidDay`／`chatTopics`／`weather`。

**⇒ 补算是确定性的，可以进门禁。** 这条是「把『从存档补算 30 天』纳入门禁」得以成立的前提。

### 附问 · 回来那一刻，现有 `drainLog` 会做什么（本单红线「零 AI」的真正对手）

这一问不在任务书五问里，但不查清就无法守住红线，故一并取证。

`drainLog` 的 AI 触发闸是 `if(state.llm.on && !e.llm && !e.llmPending)`，而开局游标是 `state.logSeenLid = -Infinity` ——

| 存档 | 日志条数 | 会触发 `enhanceChat` | 会触发 `enhanceMessage` |
|---|---:|---:|---:|
| seed 20260803 跑满 3 天 | 131 | 25 | 0 |

**即：今天每开一次页，就会为几十条旧闲聊重新掏一次钱**（对白闸不合格还会各再追一次）。这是既有行为，与补算无关；但补算产出的新条目会落进**同一个桶**，所以红线「补算全程零 AI、回来也不补生成」**光靠『补算时不调 AI』是拦不住的**，必须在这道闸上加水位线。治法见第三章。

## 二 · 两条换算口径（**决策者已裁定：两条均确认，维持现状**）

### 口径① · 1 真实分钟 ＝ 1 模拟分钟（`CATCHUP_MIN_PER_MIN=1`）

页面开着时，游戏的速率是 **1 真实秒 ＝ 10 模拟分钟**。若离开期间照这个速率折算，离开 7.2 分钟就已经推满 3 天。三条依据指向 1:1：

1. **决策者原话两句只有在 1:1 时才逐字为真**：「关十分钟，回来看到『刚才这十分钟』；关三天，回来看到『这三天』」。按页面速率折算，关十分钟＝4.17 模拟天，第一句当场不成立。
2. **待办第 2 条已议定的形状是「同步时长不同步钟点」**——这句话只有在 1:1 时才有意义（若按速率折算，说法应是「按速率折算」）。「不同步钟点」＝世界的钟点不去追现实世界的钟点，这一条本单照做。
3. 按页面速率折算的话，**封顶线会成为唯一还在生效的口径**（离开超过 7 分钟就一律封顶），「关多久看多久」整条设计等于没落地。

**决策者裁定一：确认，维持现状。** 裁定时点名保留的理由是上面第 1 条——「关十分钟看刚才这十分钟」只有 1:1 才逐字成立。
若日后要改成按页面速率折算，只改 `CATCHUP_MIN_PER_MIN` 一个常量即可（改 1 → 600），门禁会自动按新值复算全部边界断言。

### 口径② · 封顶 3 模拟日（`CATCHUP_MAX_DAYS=3`）

**先把话说清楚：封顶不是因为算不动。** 第 3 问实测 30 天只要 12.5 ms，任务书第二优先档的触发条件没有成立。设封顶的四条理由是：

1. 待办第 2 条早已议定「封顶两三天（集中可调）」，本值取其上沿；
2. 决策者原话点名的就是「关三天，回来看到这三天」；
3. **验证边界**——`sim30` 只验到 30 天，30 天以外的生存不变量无人背书。取 3 天等于给门禁留 **10 倍余量**；
4. 玩家侧：3 天＝3 张剪辑卡，一坐能看完；30 天＝30 张，没人看（第 21 单结项裁定「玩家该看的是剪辑，不是流水账」）。

超出部分**按「跳过」处理并如实告知玩家**（横幅原文见第四章）。

**决策者裁定二：确认，维持现状。** 裁定时特别要求**保留本节开头那句「封顶不是因为算不动」**——防止日后有人把它当成性能妥协随手放宽。

### 三条边界一律向「少补」倒

| 情形 | 补几拍 | 缘由 |
|---|---:|---|
| 离开不足 10 真实分钟 | 0 | 一拍＝10 模拟分钟，不足一拍不补 |
| 存档 `speed===0`（暂停中离开） | 0 | 玩家自己把城市按停了，补算不得替他松手 |
| `Date.now()` 倒流（负差值） | 0 | 绝不倒着推 |
| `meta.at` 缺失／NaN（旧档） | 0 | 绝不判坏档，静默不补 |
| 存档缺 `speed` 字段 | 0 | 按暂停处理 |

## 四 · 用户可见变化 · 文案原文逐字

**新增文案共 4 条**（其余全部沿用既有字面量，一字未改）：

1. 城市日志（未触封顶）：
   `⏱ 你不在的时候，城市自己过了 3 天。`
2. 城市日志（触封顶时，句尾追加）：
   `（离开更久，只补到封顶的 3 天，更早的没有补算。）`
3. 剪辑页横幅（未触封顶）：
   `⏱ 你不在的时候，城市自己过了 3 天（D1 08:10 → D4 08:10，跨过 3 个夜晚）。这段时间的对白与日记都没有过 AI，只有剪辑照常挑。`
4. 剪辑页横幅（触封顶时，句尾追加）：
   `　离开更久，只补到封顶的 3 天，更早的 7 天没有补算，那段日子没有发生。`

> 第 4 条里「那段日子没有发生」是有意的直说：**跳过就是跳过，不许含糊成「没有显示」。**
> 硬断言：`⚠ 补算期间出现了 N 次 AI 调用，已就地关闭本局 AI。`——结构上不可能出现，留着是为了「破了必须看得见」。

- 离开超过 10 真实分钟再打开，城市会自己往前走了（1 真实分钟＝1 模拟分钟，最多 3 模拟天）。

### 裁定三的落地口径 —— 一处必须报的偏离（宪法第 3 条：任务书与现实冲突时报告）

**裁定原文**：改成「跨过夜 **且** 剪辑条数比离开时多」才推剪辑页。

**照字面实现会有缺陷，故落地时取的是这句话的意思而不是字面**，理由是一行既有代码：

```js
w.clips.push(rec);
while(w.clips.length>CLIP_KEEP) w.clips.shift();   // html:1474，CLIP_KEEP=60
```

`w.clips` 的**条数被封在 60**。城市过了 60 个剪辑日之后，条数恒为 60，「条数比离开时多」**从此永远为假**——照字面实现的话，这条呈现规则会在第 61 个剪辑日**悄悄失效**，而且不会有任何报错，玩家只会觉得「怎么后来就不推了」。

故落地判据取 **`clipsNew` ＝「最新剪辑日变没变大」**（`clipTopDay(w)`）：它是单调的，不受保留上限影响，和「有没有出新卡」这件事一一对应。裁定要的效果（**没有新卡就别推**）逐字守住，只是量它的尺子换了一把。

门禁两条断言把这件事钉住（`harness.js`）：

| 断言 | 实测 |
|---|---|
| 构造成立：`clips` 已顶到保留上限 60 条 | 60 条 |
| 饱和之后「条数增量」恒为 0 —— 拿它当判据会在第 61 个剪辑日起悄悄失效 | `clipsAdded = 0` |
| 同一段里最新剪辑日照常前进 3 天（63 → 66）⇒ 判据取它才不会自锁 | `clipsNew = true` |
| 跨过夜但没跨 04:00 ⇒ `clipsNew` 为假 —— 这一档不推剪辑页 | 起点 D1 21:40，推 1 小时，跨 1 夜、最新剪辑日不动 |
| 畸形 `clips`（含 `null`／`d:'x'`／`{}`）跳过坏条目取最大日号；`clips` 整个不是数组 ⇒ 返回 0，绝不抛错 | 7 ／ 0 |

**改判据后的实机复测（第六章六档全部重跑）**：`B-away-60min` 那一档已由「剪辑页 · 出横幅 · 0 张卡」改为 **「现场页 · 不出横幅」**；其余五档读数与改前一致（`B-away-10h` 仍推剪辑页 1 张卡、`A-away-3d` 仍 3 张卡、AI 统计与独立计数全部为 0）。
