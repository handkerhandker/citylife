# 第 123 单 · 坏档容错二期（存档被写坏时：过闸的档必须跑得动）

> 一句话：第 92 单只给"长期小账"做过耐久体检；这一批改打**坏档**——把真实存档的每个字段逐个改成畸形值，
> 按产品自带的"坏档闸"（`worldUsable`）过一遍，**过闸的档必须还能跑**。现场抓到 **3 处真 bug**：
> `saidDay` 坏类型让游戏循环当场崩、`inbox`／`personalLog` 坏元素让循环／角色卡崩。按根因修掉
> （`saidDay` 就地在取用处重建；`inbox`／`personalLog` 的元素补进闸的白名单）。
> 版本 v108 → **v109**；**世界与门禁指纹原样**、SIM md5 `6a774115…` → **`d2bb270b…`**（只多一行治愈式）。

## 一 · 怎么打的（口径）

| 项 | 内容 |
|---|---|
| 无头普查 | 400 天"活跃玩家"底档 → 逐字段 × 坏值 × 位置（共 **2199 个畸形档**）→ `hydrate` → 过闸 → 过闸者跑 5 天 |
| 渲染面普查 | 畸形档塞进隔离浏览器上下文的 localStorage → 开页 → 点角色卡 → 换短信页，**听 pageerror** |
| 判据（与产品同一条契约） | **过闸 ⇒ 必须跑得动**；不过闸 ⇒ 走既有"挪 BAK＋开新城"，算合法结局 |
| 为什么不要求"hydrate 后一律能跑" | 产品路径本来就会先过闸（`svAgentUsable` 白名单）；绕过闸直接 step 是工具自己的事 |

## 二 · 抓到的三处（症状 → 根因 → 修法）

| # | 现场 | 症状（实测） | 根因 | 修法 |
|---|---|---|---|---|
| 1 | `w.saidDay='x'`（数字／布尔同理） | 页面循环抛 `Cannot create property 'co:clerk' on string 'x'`——**游戏当场停摆** | `pickV` 里 `(w.saidDay||{})` 只挡 falsy、挡不住真值原语；同族的 `chatTopics`／`fbRecent` 早已就地重建，唯独它漏了 | 取用处按同一句式重建（`typeof==='object' && !Array.isArray` 才认） |
| 2 | `a.inbox=[null]` | 下一拍 `decide()` 读 `m.id` 崩——**循环停摆** | 坏档闸只查 `Array.isArray(a.inbox)`，**没查元素** | 闸补 `every(m=>svObj(m)&&svStr(m.id)&&svStr(m.label))` |
| 3 | `a.personalLog=[null]` | 点开角色卡对话框读 `e.t` 崩（当页报错、弹窗打不开） | 同上（元素没进白名单）；**合法条目里 `thought` 可能是 `null`**（周记忆那几条，按实测形状写判据） | 闸补 `every(e=>svObj(e)&&svNumF(e.t)&&svStr(e.text)&&(thought 为 undefined/null/string))` |

**同类扫描**（一次打齐）：`clips`／`log`／`rel`／`flags`／`activity`／`rest`／`week`／`goal`／`giftRecv`／
`bdayCoYears`／`giftYears`／`waiting`／`sentToday`／`stats.*` 的畸形值各打一遍——**没有再崩**的（该拒的拒、该治的治）。
