## 一 · 先分清：三条边上的黑条，不是同一个病

真机截图把话说明白了（诊断浮层每一行都是判据）：

| 症状 | 读数长什么样 | 病根 |
|---|---|---|
| 竖屏**顶上一条**、横屏**左／上／下三条** | `视口 440×691 · 屏 440×744`（视口比屏小） | **容器在缩**——壳/插件替我们给系统栏让位，WebView 整个被推进安全区 |
| 竖屏**上下两条大的**（各约 190px） | `视口＝屏`，但 `地图 611×364 @ -144,190 · 边带 t190 b190` | **画面没铺满**——画布是满的，地图被"整幅看清"居中，上下留画布底色 |

一句话口径：**视口＝屏** 还是 **边带＝0**，这两行一读就知道是"外面缩了"还是"里面没铺满"。

## 二 · 三处根因与改法

### 1）容器在缩：插件把整个 WebView 塞进了安全区（第 204 单）

**怎么发现的**：真机截图 `视口 440×691 · 屏 440×744`（差 53＝上 37＋下 16）；横屏
`707×387 · 744×440`（差左 37＋上下 53）。**视口比屏幕小**——四周那圈就是黑条。
再来对源码：装在本机包里的 `SystemBars.java` 在 WebView<140 时，
`insetsHandling:"css"` 会调用 `decor.setPadding(left, top, right, bottom)` 把**整个 WebView**
推进安全区，同时把 `--safe-area-inset-*` 注入成 0；而我们自己又按状态栏高度内缩了一次
——**双重内缩**。

**改法**（`apk/capacitor.config.json`）：

```json
"plugins": { "SystemBars": { "insetsHandling": "disable", "hidden": false } }
```

安全区全交给壳自己量、页面自己躲；插件 `disable` 之后不再代劳"键盘垫起"，
壳里补一条 `挂键盘垫起()`（只垫内容区底部＝IME 高度，其余时间不垫）。

### 2）顶／左／右：不许再替系统栏和摄像头让位（第 205 / 208 单）

三小步：

- 先删掉壳里自画的**顶部渐隐层**——它按状态栏高度盖了一条实心色 `#171C26`，看着就是黑条；
- `量insets()` 末尾无条件 **`左=0; 右=0;`**（横屏左侧 37px 的"挖孔值"不再用于给 UI 让位）；
- 再补 **`上=0;`**（真机截图证明那 37px 上方**没有可见系统状态栏**，让位让出来就是一条空白）。

口径写死：**上／左／右不让位；底部照旧让位**（手势条真的会压住按钮）。

### 3）画面没铺满：画布满、地图居中（第 186 / 208 单）

竖屏截图：`地图 611×364 @ -144,190 · 边带 t190 b190` —— 画布是满的，地图被**居中**画。
根因：取景缩放用的是"整幅能看清"（`fit`），竖屏里画布比地图**高**，纵向上就留边。

**改法**（`resizeCanvas()`）：横屏/宽屏取 `铺宽 = 画布宽/地图宽`，竖屏取
`铺高 = 画布高/地图高`，取最大值——**地图真正盖满画布**，镜头改为跟随／平移：

```js
const 比地图宽 = (box.width / Math.max(1, box.height)) >= (Sim.MAPW / Sim.MAPH);
const 铺宽 = 比地图宽 ? (box.width / Sim.MAPW) : fit;
const 手机竖屏 = app.dataset.layout === 'compact-portrait';
const 铺高 = 手机竖屏 ? (box.height / Sim.MAPH) : fit;
state.view.s = Math.max(fit, 铺宽, 铺高, Math.min(13, box.width/14, box.height/10));
```

## 三 · 怎么验证（不靠肉眼、不靠"颜色差不多"）

1. **诊断浮层**（设置→视口调试，画在游戏里，截图即证据）六行读数：
   视口／屏、安全区（页面用的 ＋ 平台原始 ＋ 壳测）、画布与地图边带、帧率、设备。
2. **三个一眼判**：`视口＝屏`（容器没缩）；`安全区 t0 l0 r0`（没让位）；`边带 t0 b0 l0 r0`（铺满）。
3. **出包核对**：解包 APK，内嵌页 sha256 与仓库登记值逐字相等（改了页面没进包＝白改）。
4. **回归**：全量冒烟 ＋ 排版 8 档 ＋ 按钮 97 击 ＋ 5 分钟浸泡 ＋ 门禁九步，全绿才交。
5. 反面教训：**"把边的颜色改成和画面相近"不是铺满**——元素仍在中间，要拿**画布/元素 rect**
   当判据（第 208 单原话："别人照搬的翻车就是只改了相近色"）。

## 四 · 给《法术工坊》的对照排查（这页可直接交给那边的 AI）

我先读了法术工坊现有的壳与页面（**只读、没动它**）：

- 壳：`MainActivity.java` 已 `setDecorFitsSystemWindows(false)` ＋两栏透明 ＋运行时量 insets 下发
  `--inset-*`／`window.__sfInsets`，横屏 top 强制 0；`capacitor.plugins.json` 是 `[]`
  —— **没有装 SystemBars 插件**，所以不是"云港小事 204"那条插件路径；
- 页面：`--sat/--sab/--sal/--sar` 只用来给**菜单/固定按钮/面板**内缩，画布按
  innerWidth/innerHeight 铺满（它自己的门禁断言 canvas rect==viewport）。

因此按下面顺序查，三步能定位：

1. **先看装的是不是最新包**：法术工坊有"自检屏"（`法术工坊·自检`），先报版本号与
   `insets/isVisible/cutout`——若不是含全屏修复的那版，先装新版再说。
2. **分清"容器在缩"还是"画布内留边"**（云港小事最值钱的一条经验）：
   在页面里读三个数并截图——`innerWidth×innerHeight`、`screen`／`visualViewport`、
   游戏画布的 `getBoundingClientRect()`：
   - 视口 < 屏 ⇒ **容器在缩**（问题在壳/宿主）：确认 `decorFits…=false` 真的生效、
     `windowLayoutInDisplayCutoutMode=shortEdges`（横屏左边那条多半就是挖孔区没铺进）、
     没有任何地方再给 WebView 加 padding；安卓 15+／targetSdk 35+ 还要留意
     `windowOptOutEdgeToEdgeEnforcement` 之类的新开关是否被宿主改写；
   - 视口＝屏、但画布 < 视口 ⇒ **页内铺装**：把"画布尺寸"改回整个视口；
     **insets 只许移动 HUD/按钮，不许缩画布**；
   - 视口＝屏、画布＝屏、但**游戏内容居中留边** ⇒ **取景没铺满**：照上面第 3 条
     取 `max(画布宽/世界宽, 画布高/世界高)`，镜头改跟随。
3. **对照口径**（与云港小事逐条一致）：
   - 上／左／右 **不让位**（`上=0` 在竖屏也一样；横屏的 left/right 是挖孔/宿主残留值）；
     底部按需（手势条真会压字）；
   - **别再用渐隐/装饰层盖边**（竖横屏底部被渐隐层盖，是云港小事另一份文档里点名的翻车项）；
   - 验收拿**读数**说话：视口＝屏、边带 0、可点元素中心 `elementFromPoint` 命中画布。
