# 第 122 单 · 本地备份兜底（工作流架构；**产品代码零改动 ⇒ 不涨号**，版本仍 v108）

> 一句话：项目的"备份生命线"原定走百度网盘，但本机网盘客户端**没在跑、计划任务里也没有它**，
> 而项目又**不推 GitHub** ⇒ 210 个提交只有 F 盘一份。本单加一条**可验证的本地快照**兜底：
> `git bundle --all` ＋ 仓库外文件 zip，每天 03:30（＋登录时）由**隐藏任务**写进
> **D:\云港小事备份**（D 盘与项目所在的 F 盘不是同一块物理盘）；写完立刻 verify，
> 并真做过一次**恢复演练**（clone → 抽 app.js → `node --check` → `node harness.js` **ALL PASS**）。

## 一 · 现状取证（为什么做）

| 项 | 实测（2026-10-03） |
|---|---|
| 百度网盘 | `BaiduNetdiskUtility` 服务 **Stopped**；无 Baidu 计划任务、无启动项——"自动备份"没有在发生 |
| 既有的 backup 类计划任务 | `ShihuoGithubBackup`（**拾火**项目的 GitHub 备份，与本项目无关）＋ 5 个 Windows 自带（AppListBackup／CloudRestore／Registry） |
| 项目侧 | citylife 仓 **210 个提交**、工作树 56.5MB、`.git` 80.7MB；`.gitignore` 只排 `app.js`／`node_modules` 等**可再生**文件 |
| 盘面 | E/F 是**同一块物理盘**（HS-SSD-C4000 2TB）；C/D 是另一块（SAMSUNG 1TB）⇒ 兜底落 **D 盘**才有"跨盘"意义 |

三条口径：**只读**（`git bundle` 不写工作树、不提交、不推送）；**验不过就作废**（`.tmp` → verify → 才改名）；
**幂等**（20 小时内已有一份就跳过——所以"每天＋登录时"两个触发器不会刷爆保留位）。
