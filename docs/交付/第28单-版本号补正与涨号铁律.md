## 二、涨号铁律与门禁

> 本章写的是**三轮红队之后的最终形态**。中途的设计缺陷与治法逐条记在三.5／三.6／三.7，不回填掩盖。

### 2.1 规则

> **只要 `city-life-framework.html` 的字节发生改动，界面上的构建版本号就必须随之改变。**

### 2.2 判据为什么定在「整份文件字节」而不是「只算 `<script>` 段」

界面上那个数的标签逐字是「**构建版本／旧卡片不会自动更新，请从最新消息打开**」（`html:404`）。它对玩家的唯一用途就是**认出手里这份产物是哪一版**。故只要产物的字节变了，这个数就该变。

这**比任务书说的「游戏代码」更严**——连改一句 CSS、改一个标签文案都要涨号。取舍理由：

- 好处：**在这个文件内部零盲区**，不存在「改了但哈希没变」的缝。若只算 `<script>` 段，一处纯 CSS 的渲染回归就能整个溜过去。
- 代价：文案／样式微调也被迫涨号。判定这不算误伤——按上面那个标签的字面用途，产物变了就该换号。

### 2.3 两层判据

| | 判据 | 依赖 | 堵的洞 | 自己的洞 |
|---|---|---|---|---|
| **第一层**<br>版本对照表 | 已发版的号对不上当前 HTML 的 sha256 即判红 | **不依赖 git**，任何一份检出都能跑 | 改了 HTML 没涨号（含直推 main、含无 git 的检出） | 手工编辑对照表里的哈希 |
| **第二层**<br>git 差分 | 相对基线，HTML 变了而号没变即判红 | git 历史 | **第一层那个洞**（它看得见「HTML 变了而号没变」） | 无 git 时跑不了（CI 内已改成 fail-closed 判红） |

**第一层的判定分支**（`checkLedger`）：

| 当前号的状态 | 判 | 含义 |
|---|---|---|
| 已登记 且 哈希相等 | 绿（`MATCH`） | 产物与登记值一致 |
| 已登记 且 哈希不等 | **红（`MISMATCH`）** | **改了代码没涨号** |
| 未登记 且 恰为最大号 +1 | 绿（`NEW`）+ 醒目提示 | 施工正在一个新号上干活 |
| 未登记 且 ≤ 最大号 | **红（`BACKWARD`）** | 往回退号／占用退役号 |
| 未登记 且 > 最大号 +1 | **红（`SKIPAHEAD`）** | 跳号（规矩是一单涨一位） |
| 格式不合 `vN`（禁前导零，≤4 位） | **红（`BADVER`）** | `v36b`／`v36.1`／`V37`／`v0000037` 一类 |
| 找不到 `id="set-build"` | **红（`NOVER`）** | 把权威处整个删掉 |

`NEW` 这一档是**刻意留的**：让「涨号」成为习惯动作，而不是让「改对照表」成为习惯动作。若每次改 HTML 都要求刷新表里的哈希，那么「忘了涨号」的人会条件反射去刷表——**闸会训练出错误的反射**。这也是为什么 `--登记` 必须只新增不覆盖（见三.5 洞一）。

**第二层的基线怎么取**（三选一，按序）：

| 场景 | 基线 | 为什么 |
|---|---|---|
| CI · `pull_request` | **`merge-base HEAD × `**`github.event.pull_request.base.sha` | `base.sha` 是 base 分支的**当前头**、不是分叉点；不再求一次 merge-base 的话，PR 在飞期间 main 一前进就会误伤（见三.6 误伤三） |
| CI · `push: main` | `github.event.before`（推之前的 tip） | **否则 `merge-base(HEAD, origin/main)` 就是 HEAD 自己、差分恒为空，这一层在 main 上等于空转** |
| 本地 | `merge-base HEAD origin/main`（或 `upstream/main`） | 与 main 的分叉点。**不回退到裸 `main`**——本仓库的本地 `main` 就停在 `9398780`（v12），退回去等于拿二十几单前的树当基线（见三.7 哑闸二） |

**第二层为什么天然是「一单一号」的粒度**：基线取的是与 `main` 的分叉点，一条分支＝一单，故单里改几次 HTML 都只要求整条分支相对 main 涨一次号，中途提交不会被逐个判红。

**第二层为什么不会让历史提交无法通过**（任务书硬口径 4）：老提交是 `main` 的祖先，`merge-base(它, main)` ＝ 它自己 ⇒ 差分为空 ⇒ 直接跳过。**「只对当前及往后生效」是结构性的，不是靠写一个截止日期。** 同理，「基线必须已登记」那条**只警告不判红**的记账检查，也只在基线版本号 ≥ 对照表起点（写死的常量 `LEDGER_EPOCH = 36`）时才适用，v33 及以前一律跳过。

### 2.4 两条线索为什么选了这个组合

任务书给的两条参考线索，实测后的取舍：

- **只做 git 差分**：判据最贴切，但默认基线（分叉点）**在 `main` 上是空转**，直推 main 不走 PR 就整个漏掉；且 `actions/checkout` 默认浅克隆时根本跑不了。
- **只做哈希对照表**：任何检出都能跑，但**信任那张表**——不涨号直接改表里的哈希就能变绿。
- **两层一起**：第二层堵第一层的表篡改（它看得见「HTML 变了而号没变」），第一层堵第二层的不可用。**这是选它们的唯一理由，不是为了多写一层。** 加固轮里两层各自的短板也都单独治了（`main` 上换基线、CI 内 fail-closed、`--登记` 拒绝覆盖），见三.5。

### 2.5 落地

- 新增 `versiongate.js`（gate 第 7 个 run 步，排在 SIM 块纯净检查之前）、`version-ledger.json`（对照表）。
- `gate.yml` 的 `actions/checkout` 加 **`fetch-depth: 0`**——默认浅克隆取不到分叉点、也取不到反向自查要喂的六个历史提交。**这一行是第二层的命门，故由门禁自己断言它还在**（撤掉当场判红）。
- `gate.yml` 增传 `VERSIONGATE_BASE`（PR 基线）与 `VERSIONGATE_PREV`（push 前 tip）两个环境变量。
- `--登记` 开关把当前号与字节写进表。**只有这个开关会写盘，门禁本身绝不自动写**——自动写等于这道闸自己把自己关了。**且它只新增不覆盖**：已发版的号字节变了一律拒绝并退出 1，确需覆盖须显式 `--覆盖 --理由="…"` 并在表里留 `覆盖记录`。

## 三、反向自查实证（判红 + 不误伤两面）

> 第 20 单立下的规矩：闸立完必须把病态写法复演一遍，断言它确实被判违规。**一条恒绿的闸等于没立。**

### 3.1 拿 git 里六个真提交对喂——病态场景不是造出来的，是真实历史

 ok : 判红：第24单→第25单（真实：动了 HTML 25+/1−，号没涨） ⇒ STALE

```

 ok : 不误伤：HTML 一个字节没动（＝只改了 .md 文档的单）⇒ 判绿
 ok : 拦得住：改了游戏代码而版本号还钉在已发版的 v36 ⇒ 判红（MISMATCH）
 ok : 不误伤：改了游戏代码且涨到 v37（恰好 +1）⇒ 放行（施工中的新号）
 ok : 拦得住：把号往回退到 v35 想绕过去 ⇒ 判红（BACKWARD）
 ok : 拦得住：跳到 v99（规矩是一单涨一位）⇒ 判红（SKIPAHEAD）
 ok : 拦得住：拿 "v0000037" 冒充涨号 ⇒ 判红（BADVER）
 ok : 拦得住：拿 "v36b"／"v36.1"／"V37"／"v035" 冒充涨号 ⇒ 判红（BADVER）
 ok : 拦得住：把 id="set-build" 整个删掉想绕过去 ⇒ 判红（NOVER）
── 反向自查 · 第二层（合成场景，每次都跑，不只在退化时跑） ──────
 ok : 判红：HTML 变了、号没变
 ok : 判绿：HTML 没变（＝只改文档／只改门禁脚本的单）
 ok : 判绿：HTML 变了、号也涨了
```

### 3.5 加固轮：对这道闸自己做了一次对抗性评审，堵掉五个洞

闸写完后又拿三个视角（误伤／规避／CI 机理）对它做了一轮红队，**实测出一条畅通的漏网主干**并已堵死。逐条：

| # | 洞 | 实测的漏网路径 | 已改成 |
|---|---|---|---|
| 1 | **`--登记` 是那个洞的一键版** | 第一层判红时，报错信息里唯一一句可复制的命令就是 `--登记`；而它对已登记的号是**静默覆盖**，跑一下就绿了、退出 0。「必须刻意为之」是错的，这是**照着报错信息干活就会** | `--登记` 改成**只新增不覆盖**：已发版的号字节变了一律拒绝、退出 1，并指出正确做法是先涨号。确需覆盖须显式 `--覆盖 --理由="…"`，且在对照表里留一条 `覆盖记录`，**留在 diff 里给复核看** |
| 2 | **第二层在 `main` 上恒空转** | `push: main` 时 `merge-base(HEAD, origin/main)` ＝ HEAD 自己、差分恒为空。合起来：改代码 → `--登记` → 直推 main ＝ 两层全绿 | `gate.yml` 增传 `VERSIONGATE_PREV: ${{ github.event.before }}`，push 事件用「这一推之前的 tip」当基线。第二层在 main 上**不再空转** |
| 3 | **git 取不到基线时 fail-open** | 浅克隆／假 git／无 remote 的 zip 检出 ⇒ 第二层 SKIP 且退出 0，恰好关掉唯一能拦第 1 条的那一层 | 分环境 fail-closed：`GITHUB_ACTIONS==='true'` 时取不到基线**一律判红**（CI 里 git 必然可用且 `fetch-depth: 0` 已设，SKIP 本身就是故障信号）；本地／zip 保持 SKIP。另把 git 的 stderr 打出来，否则「为什么取不到」永远查不出 |
| 4 | **对照表起点可被同一个 PR 撑大** | 「基线必须已登记」那条用 `Math.min(表里的号)` 当起点，而对照表**正是这道闸要保护的文件**——把它剪到只剩一条高号，豁免面就跟着涨 | 起点写成常量 `LEDGER_EPOCH = 36`，另加一条结构断言「对照表起点未被剪短」，剪表当场判红 |
| 5 | **`v0000037`／`v3600` 被当成合法涨号** | `Number('0000037')` 吃掉前导零 ⇒ 大于最大号 ⇒ 放行 | `verNum` 收紧成 `/^v(0\|[1-9]\d{0,3})$/`；并新增「新号必须恰等于最大号 +1」——把「一单涨一位」这条规矩本身也变成机器判据（跳号判 `SKIPAHEAD`） |

另加固两处：`gate.yml` 里「`node versiongate.js` 这一步还在不在」与「`fetch-depth: 0` 还写着没有」由门禁自己断言（撤掉 `fetch-depth: 0` 当场判红）；真实历史自查由**全有全无**改成**逐条跳过**，某个 sha 不可达只跳那一条并印出是哪个，合成场景则**每次都跑**作为「不恒绿」的下限保证。

**五个洞的堵法逐个实测**：

```
洞一 改了代码不涨号，再跑 --登记 想绕过去
     → 拒绝登记：v36 是已发版的号，而 HTML 字节已变（登记 5fa61878… ≠ 实际 7a660044…）
       正确做法：先把 html:405 的号改成 v37，再跑 node versiongate.js --登记
       退出码=1 · 对照表逐字节未被写入 ✓

洞二 直推 main：改了游戏代码，号仍是 main 上的 v33
     → 基线 005f0fe6（CI 传入的 push 前 tip（github.event.before）） · 基线版本号 v33
       FAIL: 第二层 · 涨号判据：…相对基线已改动，而构建版本号两头都是 v33 ⇒ 改了代码没涨号
       退出码=1

洞三 第二层取不到基线
     → 本地 退出码=0（SKIP）　／　GITHUB_ACTIONS=true 退出码=1（判红）

洞四 撤掉 gate.yml 的 fetch-depth: 0
     → FAIL: gate.yml 的 checkout 仍写着 fetch-depth: 0（撤掉它，第二层在 CI 上就取不到基线）
       退出码=1

洞五 把对照表剪成只剩一条 v99
     → FAIL: 对照表起点仍是写死的 v36（剪短对照表就能撑大「基线免登记」的豁免面）
       退出码=1
```

**正路仍然顺畅**（不误伤的另一面）：改代码 → 把号涨到 v37 → 门禁放行（`NEW`，退出 0，中途随便改）→ 收工 `--登记` → 全绿。实跑逐步确认。

### 3.6 第二轮红队：闸把自己变成了误伤机器，三处已治

第一轮只盯「漏网」，第二轮换了「误伤」这个视角，**在临时造的真 git 仓库里复现出三处误伤**——其中一处会让 `main` **恒红**。这三处比漏网更危险：漏网只是没拦住，恒红是整条流水线停摆。

**误伤一（致命）· 记账检查让 `main` 恒红，且惩罚的是下一个无辜的单。**
原设计里「基线必须已在对照表里」是判红项。实测：第 29 单正确涨号到 v37 但收工忘了 `--登记` → 它自己的 PR 全绿 → 合进 main → **此后任何一个单都红**，包括只加一行 `README.md` 的纯文档单：

```
 ok : 第一层 · 版本对照表：v37 尚未登记且恰为表内最大号 v36 的下一位
 ok : 第二层 · 涨号判据：city-life-framework.html 相对基线零改动 ⇒ 本层不适用
FAIL: 基线 v37 已在对照表里且哈希对得上 —— 这一条堵的是「上一单发了版却没补登对照表」
1 FAILURES · 退出码=1
```

> 治法：**降级成只警告不判红**（`WARN:`）。理由写进代码注释：它验的**不是铁律**（铁律只说「HTML 字节变了、号必须变」），它验的是记账，而且验的是**别人的**账；**门禁在 main 上恒红等于没门禁**。铁律本身由两层完整守住，少了这条只是「那个号在第一层上暂时没意见」，第二层照样拦得住改了代码不涨号。治后同一场景：`WARN: … ⇒ 上一单发了版却没补登对照表` + **退出码 0**。

**误伤二（重要）· 同一单里涨过号之后再改一次 HTML 就被判红，而这在本项目是常态。**
一旦跑过 `--登记`，那个号的哈希就被冻住；同一单里再动 HTML（本项目「主体改动 → 自查 → 决策者裁定落实」这个三段式，第 26 单三条、第 27 单两条动 HTML 的提交都是这个形状）当场 `MISMATCH` 判红，而报错还劝你「涨一位」——照做会让一个单吐出 v38/v39/v40。

> 治法：判据的分水岭从「**登记过没有**」改成「**发出去了没有**」。用 `git show origin/main:…` 读出 main 上现在挂的号：当前号 **大于** 它 ⇒ 这个号还没发版 ⇒ 字节再变只提示不判红（`WIP`），`--登记` 也可以直接刷新、不必 `--覆盖`。取不到 main 的号时退回保守侧判红。治后实测：`ok : v38 登记过但字节又变了；而 v38 还没发到 main（main 上是 v37）⇒ 本单施工中的号，本层放行`，退出码 0。

**误伤三（重要）· CI 的基线取的是 `main` 的当前头，不是分叉点。**
`github.event.pull_request.base.sha` 是 base 分支的**当前头**（GitHub 在 synchronize 时会刷新它）。PR 在飞的期间 main 一前进，无辜的单就会被拿去和一个它从没见过的树比。

> 治法：拿到 `base.sha` 之后**再求一次 `git merge-base HEAD <base.sha>`**。这样「基线取的是与 main 的分叉点，一条分支＝一单」这句话在 CI 上才是真的——**在此之前它不是真的**。

另治四处：`checkBaseRegistered` 抽成纯函数并**补进反向自查**（此前那段是内联代码，物理上喂不到，于是出现过「门禁刚误伤完一个纯文档单，紧接着自查向你保证它不会误伤文档单」的自相矛盾）；`checkBump` 补 `DOWN` 判据（号往回退）；`VER_RE` 容忍单引号与等号两侧空格（等价写法判红也是误伤）；新增 `.gitattributes` 写死 `city-life-framework.html -text`（否则 `core.autocrlf=true` 的机器上工作树哈希与 git blob 哈希对不上，门禁对零改动的单也会恒红）。反向自查里六个短 SHA 换成 40 位全 SHA；「三单漏涨」那条断言放宽成「至少含这三单」，免得日后往 `.历史` 补一笔旧账反而判红。

**三处误伤治完后，第一轮堵的五个洞逐个回归复测，全部仍然堵着**：

```
洞一 改了 HTML 但号仍是 main 上的 v38 → --登记
     → 拒绝登记：v38 是已发版的号，而 HTML 字节已变 · 退出码=1 ✓
洞二 直推 main 改代码不涨号
     → FAIL: 第二层 · 涨号判据：…两头都是 v38 ⇒ 改了代码没涨号 ✓
洞三 CI 内取不到基线 → 本地 退出码=0 ／ GITHUB_ACTIONS=true 退出码=1 ✓
洞四 撤掉 fetch-depth: 0 → 判红 ✓　　洞五 剪短对照表 → 判红 ✓
```

**这一轮的教训本身值得记档**：第一轮红队只问「拦不拦得住」，闸就朝「宁可错杀」的方向长；**误伤会把闸变成必须被绕过的东西，那比漏网更快地让它失效**。故反向自查的两面必须同权重——判红那面和不误伤那面，都得有真实场景喂进去。

### 3.7 第三轮红队（CI 机理）：补登这件事终于有闸兜了，另治五处

第三轮换 CI 机理这个视角，又实测出一条**误伤与漏网首尾相接**的链，以及两处「印着 ok 但事实相反」的哑闸。

**链条（重要）· 漏登的号能绿着落到 main，而下一单反被判红，且门禁给的改法会复刻本单要根治的病。**
实测：涨号到 v37 但收工忘了 `--登记` → 第一层判 `NEW` 放行、第二层判 `BUMPED` 放行 ⇒ **PR 与 push:main 两道都不响，v37 未登记地落到 main**。下一单老实涨到 v38 时反而 `FAIL: v38 跳号了…本单应为 v37` —— **照做就等于让 v37 挂两份不同字节的产物**，正是第 28 单要治的那个病的复刻。

> 治法两条。①**把「补登」的闸落在 push 事件上**：那一刻这份产物正在落到 main，是「已发版」的定义时刻，故此时第一层必须是 `MATCH`，`NEW`／`WIP` 一律判红。不放在 PR 上，是因为 PR 期要求 `MATCH` 就等于每改一次 HTML 都得重跑 `--登记`——那正是「让改对照表成为习惯动作」，闸会训练出错误的反射。②`SKIPAHEAD` 的报错补一句反向提醒：「若 v(N+1) 其实已经发到 main、只是没人补登，**别照本条改号**」。
> 实测：`PR 事件 退出码=0`（施工期允许）／`push:main 退出码=1` + `FAIL: 落到 main 的号必须已登记进对照表（实测第一层判定＝NEW）`。
> 这一条同时让 3.6 的记账 WARN 有了真正的兜底：漏登不再靠下一单来偿，而是在它自己合并那一刻就响。

**哑闸一 · `gate.yml` 自查的正则不锚行，一行注释就能骗过。**
实测：把 `fetch-depth: 0` 改成 `1`、上面留一行 `# 曾经写过 fetch-depth: 0`，门禁**照印 ok** —— 比没有这条检查更坏，它主动印了一句与事实相反的话。
> 治法：正则锚到行首（`/^\s*fetch-depth:\s*0\s*$/m`）；**并补一条不读 yml 的自证**——CI 内断言 `git rev-parse --is-shallow-repository === false`。浅不浅是客观事实，改注释骗不了。实测治后：`FAIL: gate.yml 的 checkout 仍写着 fetch-depth: 0（第二层的命根子；锚行首，注释骗不过）`，退出码 1。

**哑闸二 · 本地基线会退回裸 `main`，而本仓库的本地 `main` 停在 `9398780`（v12，第 1 单）。**
实地查证：`git rev-parse main` = `9398780`（"Add files via upload"），其 HTML 的构建版本号是 **v12**。`origin/main` 一旦取不到（`clone --single-branch`、remote 改名、久未 fetch），第二层就会拿一个二十几单之前的树当基线，变成橡皮图章。
> 治法：**去掉裸 `main` 回退**，只认 remote-tracking ref（`origin/main`／`upstream/main`）。

另治三处：`VERSIONGATE_BASE` 不可达时**继续往下试**别的基线来源（此前直接放弃，导致本机残留一个过期环境变量就能让第二层整块消失且不判红）；push 事件 `github.event.before` 为全 0（首推／force-push）时改用 `HEAD^1`（此前退回的 merge-base 在 `push:main` 上恒等于 HEAD、差分必空，**且因为「拿到了一个 sha」连 fail-closed 都不会触发**，那一推等于没验）；真实历史六条不可达时在 CI 内改判红（与第二层 fail-closed 口径一致）。

两处卫生：`execSync` 字符串拼接改成 `execFileSync` 传数组（基线 sha 来自 CI payload 与环境变量，不该有机会被当成 shell 命令）；报错信息里写死的 `html:405` 改成算出来的位置——**那正是本单交接说明:9 刚批评过的「停在第 1 单从未跟进的写死数字」**，闸自己不该再犯一次。

**三轮之后，本地与 CI 两种模式各跑一遍，均 `涨号铁律 ALL PASS`。**

## 四、这道闸挡得住什么、挡不住什么（照实登记，不粉饰）

任务书要求：若判断做不到「零误伤且零漏网」，**照实报告边界**。结论是**做得到零误伤，做不到零漏网**。

### 挡得住

| 情形 | 由哪一层拦 | 实测 |
|---|---|---|
| 改了 `city-life-framework.html` 任意一个字节而没涨号 | 两层都判红 | 三.2、三.1 |
| 把号往回退、占用已退役的号、跳号 | 第一层（`BACKWARD`／`SKIPAHEAD`） | 三.4 |
| 拿 `v0000037`／`v36b`／`V37` 冒充涨号 | 第一层（`BADVER`） | 三.4 |
| 把 `id="set-build"` 整个删掉想绕过去 | 第一层（`NOVER`） | 三.4 |
| **不涨号、想靠 `--登记` 一键抹平** | `--登记` 直接拒绝，退出 1 | 三.5 洞一 |
| **直推 `main` 不走 PR** | 第二层（用 `github.event.before` 当基线） | 三.5 洞二 |

### 挡不住

1. **`city-life-framework.html` 以外的对外产物。**
   `assets/apartment.png`、`assets/characters.png`（**不是内联的**——`html:3149` 是运行时按路径去取：`img.src=ASSET_BASE+'/'+file`；`grep -c 'data:image/png;base64' city-life-framework.html` ＝ **0**；`tools/asset-pipeline/README.md` 明写这两张是「唯一的对外产物」）与 `functions/relay.js`（部署到边缘的 AI 中转函数，gate 对它只做 `node --check`）。
   **这是最实的一条**：换一张 `characters.png`，玩家一定看得见，而 HTML 一个字节不动 ⇒ 本闸全绿。
   未擅自扩大——任务书的口径就是这一个文件。**是否升成「产物清单哈希」，列入等决策。**
2. **不涨号而直接篡改对照表里当前号那条的 `sha256`（且 git 不可达时）。**
   加固后这不再是「照着报错信息干活就会」（`--登记` 已拒绝覆盖），而是**必须手工编辑 JSON**；且第二层在有 git 时照样判红（它看见 HTML 变了而号没变）。剩下的缺口只在「手工改表 **且** git 不可达 **且** 不在 CI 里」这个交集上。表是仓库文件，改它一定留在 diff 里。
3. **把 `versiongate.js` 从 `gate.yml` 里删掉、或把脚本本身改成恒真。**
   任何门禁都挡不住自己被删——删了它就不会跑，它的自查也就不会响。只删脚本不删 YAML 会 `MODULE_NOT_FOUND` 判红，故规避必须**同时动两处**，两处都在同一个 PR 的 diff 里。**靠评审，不靠闸。**
4. **号涨了但涨得「不该涨」。**
   闸能验「变了没有」「是不是恰好 +1」「格式合不合法」，**验不了「这一单算不算一版」**——那是人的判断。
5. **一个单里第二次改 HTML 时**，若当前号已登记（如本单的 v36），第一层会要求先涨号。
   这不是漏网也不是误伤，是设计：**已发版的号是冻结的**。正常流程（在未登记的新号上干活）中途随便改，收工前登记一次即可，实跑已确认顺畅（三.5 末）。

### 一句话边界

**「`city-life-framework.html` 改了而号没变」这一件事，零漏网、零误伤。**
射程之外三样，照实说：**`assets/` 与 `functions/` 本闸不管**（第 1 条，最实的一条）；**门禁自身被删除，靠评审**；**「该不该算一版」，靠人。**

## 九、踩坑备忘（本单沉淀两条）

1. **「每单收工记得改一下」这种规矩，没有机器闸就等于没有。**
   三条可迁移的教训：①**零 reader 的量必然漂移**——没人读、没人验的数，漂了不会有任何反馈回来；②**「文档与代码互相自洽」不等于「对」**——这三单的文档和代码完全一致，一起错而已，故自洽性检查抓不到，只有拿**外部事实**（HTML 字节的哈希）对表才抓得到；③**漏账会自我掩盖**——第 25 单漏了之后，第 26 单照抄「代码基线：v33」反而显得是对的，**越漏越像常态**。

2. **闸的反向自查能拿真实历史喂就别造合成场景。**
   好处有三：证的不再是「能拦住我编的病」而是「当初就该拦住那三单」；正反两面都由历史给出，不存在「构造得太巧所以恒绿」的嫌疑；样本永远不会过期。代价一条：依赖 git 历史可达，故 `gate.yml` 须显式写 `fetch-depth: 0`，取不到时退回合成场景并**如实印 SKIP，不许静默变绿**。
