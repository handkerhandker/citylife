# 第 85 单 · 门洞记号（零素材：门框柱 ＋ 地垫）

> 一句话：待办里挂着的观感账——「**2 格门洞现为纯地板留口，无门框／地垫记号，易被误认为断墙**」。
> 本单**不动素材**，用画布画两样东西补上：门洞两侧各一小节**门框柱**（暖金）＋ 门内半格**地垫**（淡金）。
> 数据只用既有的 `ROOMS[].door`（x／side），一处取词、只读、不进 SIM ⇒ **三个指纹全部原样**，只有界面涨号 v80 → **v81**。

## 一 · 缘由与为什么零素材也能做

待办原文建议"走素材流水线（门框贴条或地垫小件），随视觉层二期·室内篇同车最省"——
但那要等素材那一条线（属"先出方案"的大改动）。本单换了个更便宜的路子：
**门的位置本来就在 `ROOMS[].door` 里**（第 12 单放样时就登记了 x ＋ side），
门框与地垫不过是两个矩形——**画出来就行，不必做素材**。

## 二 · 设计（一处取词、只读）

```js
function 门洞记号(r){
  const s=state.view.s, dx=r.door.x+0.5, 底=(r.door.side==='b');
  const y=sy(底 ? (r.y+r.h) : r.y);              // 门线：底门取房间下边、顶门取上边
  ctx.fillStyle='#b6924a';                        // 门框柱：门洞两侧各一小节
  ctx.fillRect(sx(dx-0.5), y-2, max(2,s*0.12), 4);
  ctx.fillRect(sx(dx+0.5)-max(2,s*0.12), y-2, max(2,s*0.12), 4);
  ctx.fillStyle='rgba(182,146,74,.30)';           // 地垫：门**内侧**半格
  ctx.fillRect(sx(dx-0.35), 底 ? y-s*0.55 : y+s*0.1, s*0.7, max(2,s*0.45));
}
// draw()：房间循环（含 roomTile）**之后**统一画一遍——被拼合图接管的公寓三间也吃得到
for(const r of Sim.ROOMS) 门洞记号(r);
```

| 要件 | 落成 | 为什么 |
|---|---|---|
| 门框柱 | 门洞两侧各一小节（宽 `max(2,s*0.12)`、高 4px） | 门洞宽度是 1 格，柱子贴在两侧 ⇒ 一眼看出"这是个门" |
| 地垫 | 门**内侧**半格（宽 0.7 格、高 0.45 格） | "内侧"由 `door.side` 决定：底门往上、顶门往下——这一步是判据的核心 |
| 调用位置 | 房间循环**之后**、广场常设件之前 | 公寓三间被拼合图接管（`continue` 跳过房间循环），放循环后就都吃得到 |
| 数据来源 | 只读 `ROOMS[].door` | 零新增状态、零 rng ⇒ 指纹原样 |

## 七 · 已知接受项与盲区（照实登记，不粉饰）

1. **只有门框与地垫两样**：没有门把手、门牌号、开合动画（那些要么要素材、要么要状态，属另一单）。
2. **两格门洞只画一对柱子**：公寓的宽门洞是拼合图自带的"留口"，本单只在其两侧补柱；
   真要"两扇门"的观感得改拼合图（素材那一条线）。
3. **颜色跟路灯/摊位同族的金**（`#b6924a`）：好不好看属口味题；要调只改这一处色值。
4. **`s` 很小时（手机档 s≈13）柱子只有 2px 宽**：这是有意压到最小可辨尺寸，再细就看不清了。
