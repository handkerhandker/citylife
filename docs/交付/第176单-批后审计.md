## 四 · 发现的真问题：门禁指纹漂移了 37 份文档没人复核

**去病**：第 172／174／175 三单的交付件都写着「门禁指纹 `a0586627…` 原样」，
可 `a0586627…` 是第 118 单（v105）的实测值——之后的单**没有真的重新量过**。

**取证（本单实测，用 `git show <提交>:city-life-framework.html` 逐版本复算）**：

| 历史点 | 提交 | `node sim30.js` 输出的 md5 |
|---|---|---|
| v105 第118单 | `da0654c` | `a0586627bb422cbdd2bfc04b904d342f` |
| v112 第126单 | `121e4fb` | `a0586627bb422cbdd2bfc04b904d342f` |
| v133 第165单 | `39f3c4f` | `a0586627bb422cbdd2bfc04b904d342f` |
| v138 第170单 | `97b1137` | `a0586627bb422cbdd2bfc04b904d342f` |
| v139 第171单 | `062c2e7` | `a0586627bb422cbdd2bfc04b904d342f` |
| **v140 第172单** | `5c81215` | **`b6cf5bf54d6a04c6818678908dee6c68`** |
| **v142（当前）** | HEAD | **`b6cf5bf54d6a04c6818678908dee6c68`** |

- 结论：**变化点恰好是第 172 单**（出门采访＝真行为改动，世界指纹也从 `aca433e7…`
  变成 `5d4e281f…`）；170／171 两单写「原样」是对的，**172／174／175 三单写错了**。
- `sim30.js`／`worldsig.js` 自 v105 起零改动（`git log da0654c..HEAD -- sim30.js` 为空），
  所以这个变化全部来自世界本身，不是门禁措辞。

**根因**：世界指纹由门禁每次都打印（有 reader），门禁指纹只能人工跑 `node sim30.js | md5sum`
抄数——**零 reader 的量必然漂移**（与第 28 单「版本号没有 reader 就漏涨三单」同型）。

**治法（同第 28 单的正解：把数与字节绑死、对不上就红）**：

1. 新台账 `fingerprint-ledger.json`：记当前三指纹（版本／世界／门禁／SIM 块 md5）＋历史；
2. 新探针 `tools/fingerprint/probe.cjs`（**冒烟档 1**）：从**当前 HTML 现解**
   （写临时目录跑，不读仓库里可能过期的 `app.js`）算出三个数，与台账逐个对账——
   对不上即判红并打印处置办法（真动了世界就 `--登记` 更新台账，并在交付件写明；
   没动的单对不上就先查根因）；
3. 登记表 70 → **71 支**（档 1 20 → 21），`--列表` 复核 71/71 无漏登记；
4. 交接说明「指标与退化检查」节补一条「**三指纹对账（第 176 单立，机器闸）**」，
   把当前值与这次漂移的结论入档。

**故障注入（证明这闸不是恒绿）**：把台账里的门禁指纹人为改成 `0000…` ⇒ 探针当场判红
