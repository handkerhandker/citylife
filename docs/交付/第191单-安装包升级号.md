# 第 191 单 · 安装包升级号（versionCode 逐包递增）—— 不涨号·仍 v155

> 一句话：拆包实证——**v145 到 v155 全部 `versionCode=1`**（Capacitor 模板默认值从没动过）。
> 真机反馈"装了新版啥变化都没有"的**头号嫌疑**就是它：同版本号有些安装器不当"更新"处理。
> 本单把升级号接进打包链：`versionCode = 1000 + 游戏版本号`、`versionName = vN`，由脚本自动写入——
> **读不到版本号就构建失败**（宁可红，不再出 `versionCode 1` 的包）。

## 二 · 改了什么（全在打包链，游戏 HTML 一字未动）

- **新增 `apk/set-version.cjs`**：读 `www/index.html` 的 `id="set-build">vN` → 把
  `android/app/build.gradle` 写成 `versionCode 1000+N`、`versionName "vN"`；读不到版本号 ⇒ 退出码 1。
- **`apk/build-apk.bat`**：`sync-www` 之后、`cap sync` 之前加一步 `node set-version.cjs`。
- **`apk/android/app/build.gradle`**：按新规则写入 v155（`1155`／`v155`）。
- **`apk/README-APK.md`**：打包步骤与"升级号"口径写进文档。
