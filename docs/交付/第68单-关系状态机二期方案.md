## 一 · 为什么是"方案"而不是"开工"

关系状态机要**新增一处世界状态**（`ag.rel`）＝改结构。本项目的改动分级写得很清楚：
**大改动先出方案、决策者点头再动手**；而待办里「关系状态机」本来就挂在"已登记（暂不动）"那一行。
所以本单只做方案这一件事，把"要不要做、做到哪一档"摆到你面前，一句话就能解锁。

**明确不抄**：恋爱／结婚／多人好感互斥；用钱买关系；负关系。

## 三 · 方案要点（全文见 `docs/规划/关系状态机二期方案_v1.md`）

1. **数据**：`ag.rel = { a2:{v, day}, … }`——**每人一份他视角的半张表**（A 觉得熟、B 未必）；旧档缺字段就地补 0。
2. **涨落**：当天第一次和某人说话 **+1**（同日再聊不加）；生日那天说了祝福 **+3**；连续 3 天没说话 ⇒ 第 4 天起每天 **−1**、**落到本档下限就停**；上限 60、下限 0；**全确定性、零随机、零 AI**。
3. **档位**：生疏 0–9／点头之交 10–19／熟 20–34／老友 35–49／家人一样 50–60。
4. **外显**：角色页那行「常聊」升级为「和 X · 熟（28）」；剪辑层加 `rel_up`／`rel_cold` 两项；周记忆压一句。
5. **不夺走**：关系回落**只动这一个数**——不碰钱、不碰饭、不碰上班与睡觉（照第 22／46／49 单那条红线）。
