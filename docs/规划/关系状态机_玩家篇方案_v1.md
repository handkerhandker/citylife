# 关系状态机 · 玩家篇方案 v1（你在他们心里的分量）

> 一句话：住户之间已经有 A 档（会涨会落的关系值）／B 档（会改行为）／C 档（生日已联动）——
> 可**玩家这一侧**没有一条账：短信、留言、惦记、"等你回话"、回城弹窗、日记全都在跑，
> 但**没有一处记得"你和他"**。本方案把它补上：每人一个 `ag.relYou`（他在你这里的分量），
> 涨落规则照住户间那套，回报分三期（**先做零行为的一期**）。
> 状态：**只出方案，未动一行产品代码**（照第 105 单·B 档方案先例）。

## 一 · 为什么做（缺口与出处）

**缺口（本项目的原话）**：第 91／96 单登记的"仍挂着的"第 ④ 条——**"玩家不在关系网里"**。
现在的玩家通道各管各的：第 74 单"惦记"（一周没来信他念叨一句）、第 76／77 单留言、
第 98 单"等你回话"（读了信要回）、回城弹窗、日记——**都不带"你和他"的历史**，
发一百条和发一条，他的反应一样。

**出处（同类作品里，这本来就是"关系"的原始形态）**——2026-10-03 实测 HTTP 200：

| 作品 | 原文 | 本项目的用法 |
|---|---|---|
| 星露谷 wiki·Friendship | 「**Each day, not talking to a villager will slightly decrease their friendship** unless their heart meter is full.」「The friendship points are **multiplied on their birthday (×8)**」 | 长期不联系会掉（**掉到档位就停**）＋生日当天分量不一样 |
| Nookipedia·Friendship（动森） | 「**+1 point — speaking to the villager for the first time each day**」 | **每天第一次**说话才算（防刷） |

★关键一层：这两条口径在本作里，第 88 单是**移植到住户之间**去用的（`ag.rel`）——
而在星露谷／动森里，它们本来就是**玩家 ↔ 村民**的机制。玩家篇＝把它**接回原处**。

## 二 · 数据形状（一处定义、存档友好、默认不搅世界）

```
ag.relYou = { v: 0–60, day: 最后一次互动的日号 }      // 每位住户一条：他在你这里的分量
```

| 决定 | 理由 |
|---|---|
| **每人一条**、挂在人身上（不是另开一张城市表） | 随存档走（`serialize` 全字段拷贝）、旧档缺字段就地补 0（照 `ag.rel` 先例） |
| 上限沿用 `REL.cap`（60）、档位沿用**同一张** `REL_TIERS`（生疏／点头之交／熟／老友／家人一样） | 一处定义；外显文字与住户间一致，不新造第二套词 |
| **只存单向**（他→你） | 玩家侧没有可观测的"他说了什么"来分开记两半；**你在他心里的分量，全部由你的行动驱动**（发信／回话／留言本来就记在这一条上）——语义上它就是"你俩的来往" |
| 不新增世界级状态 | 不碰 `w.stats`、不碰日志墙之外的东西；**你不发声时，逐拍与改前一字不差**（见第五节） |

## 三 · 涨落规则（照住户间那套，数值一处可调）

| 事件 | 涨／落 | 出处／先例 |
|---|---|---|
| **那天你给他发了第一条**（短信／回话／留言都算） | **+1**（一天一次，防刷） | 动森"每天第一次说话" |
| 你的「生日快乐」**正好在他生日那天**发出 | **+3**（同一天再发不加） | 星露谷"生日 ×8"的本作映射（住户间就是 +3） |
| **连着 3 天**你一条消息都没有 | 第 4 天起每天 **−1**，**落到本档下限就停** | 星露谷"长期不联系会掉、掉到档位停" |
| 上限 | 60（`REL.cap`） | 与住户间一致 |

**不夺走**（照第 22／46／49 单那条红线）：这几条只动 `ag.relYou` 一个数——
不扣钱、不扣饭、不影响他的上班与睡觉；**掉档不撤回任何已经给过的东西**（照第 91／96 单"交过心不可逆"先例）。

## 四 · 行为回报（读关系）——建议分三期，**先做 ①**

### ① 只记 ＋ 看得见（**零行为改动**，一单可落）
- 角色页／角色卡加一行「**和你**」：档位词 ＋ 一句温度（空账照实说"还没说上过话"）；
- 往来记录顶上那行加档位（与第 98 单"等你回话"那一行并排）；
- **不改变任何行为**：他只是多知道"你俩走到哪一档了"（与第 67 单·关系一期同一种做法）。

### ② 回应读档位（动"回应层"，不动世界）
- 回信／留言的**暖话池按档位选**：生疏＝客气、熟＝随便、家人一样＝直呼其名；
- 「**等你回话**」的窗口按档位延长（第 98 单那条：等得久的人更少，朋友等得更久）；
- 「惦记」那句的频率按档位（第 74 单：熟人超过一周没信才念、生人照旧）。

### ③ 节日／生日读档位（与关系 C 档②·节日那一半**天然同车**）
- 生日祝福的回信按档位换语气；灯节夜给你的那句专属话按档位；
- 三期都是"把已经存在的那句话换个池子"，**不新增抽签**（照第 48／65 单先例）。

## 五 · 验收口径（每期都照这个来）

1. **默认路径逐拍不变**：`w.t` 不推进短信时，与改前**逐字段一字不差**——这是"玩家不发声，世界照旧"的机器证据
   （也是①期三个指纹全原样的依据）。
2. **涨**：发信 → `v+1`，且**一天只加一次**；生日当天发「生日快乐」→ +3；跨档位落**一行日志＋事件锚**（照第 88 单）。
3. **落**：连续 3 天不发 → 第 4 天起 −1；**落到本档下限就停**（不掉穿）。
4. **反向自查（每条都要"故意写坏必须判红"）**：把 +1 抹成 0 ⇒「发信会涨」判红；把掉档抹平 ⇒「长期不发会凉」判红。
5. **探针（新工具）**：`tools/rel-audit/you-probe.cjs`——模拟三种玩家节奏（每天一条／隔天一条／整月不发），
   打印四人的档位轨迹与跨档点；门禁按真值读表，不另抄一份规则。
6. **指纹记账**：①期只动显示层 ⇒ 世界／门禁／SIM 三指纹**全原样**；②期动的是回应层（SIM 块）⇒
   SIM 必变、世界指纹看它是否落在 30 天窗口内（**大概率不落**，因为默认不开短信）；③期同②。

## 六 · 待拍板（三件）

1. **做不做玩家篇**？我的推荐：**做①期**——零行为、可逆、马上看得见；②③ 期等①期落地后按手感再定。
2. **档位表**沿用住户那张（生疏／点头之交／熟／老友／家人一样）还是给"你"另起一套名字？
   （推荐沿用：一处定义、外显一致。）
3. **"会掉档"要不要**？这与住户间那条口径题是**同一句问话**——你若答"掉"，两边一起掉；答"不掉"，两边都不掉。
